# ADR 0030：把提供方 Strict 输出视为不可信输入

- 状态：已接受
- 日期：2026-08-24

## 背景

DeepSeek 官方文档声明 Beta Strict Tool Calling 会使函数参数符合 JSON Schema，正式端点的 7 次小样本探测也全部通过。但真实批次 `20260824-132715-001` 的 420 条分析中，一条严格工具参数把字符串枚举输出为未加引号的 `non_negative`；携带错误反馈后的第二次调用逐字段再次产生同类非法 JSON。另有一条流式文字请求超过 15 分钟未结束，因为原共享读取超时为面向多模态请求设置的 600 秒。

因此，能力探测只能证明接口可用，Beta Strict Tool 只能降低格式错误概率，不能成为 ThreadSnap 的最终信任边界。针对某个缺引号枚举增加替换规则也不能覆盖缺逗号、缺括号、尾逗号、未加引号字段等同类问题。

## 决定

1. DeepSeek 继续使用单一强制 Strict Tool 和最小七字段 Schema，作为提供方侧第一层约束；千问 JSON Object 和本地模型协议不变。
2. 工具参数先使用标准 JSON 解析。只有 DeepSeek 严格工具参数发生 JSON 语法错误时，才进入本地结构恢复；其他模型不共享该适配。
3. 结构恢复同时使用固定版本 `json-repair` 的通用候选和 JSON 错误点附近的单结构字符编辑。候选相对原参数只允许增删 JSON 标点、引号、转义符和空白；任何中文、英文、数字等语义字符变化都立即拒绝。
4. 每个候选必须从零通过：无重复字段、精确七字段、禁止额外字段、Pydantic 类型与枚举、业务字段关系、后端模态补齐和输入身份校验。只有唯一完整结果成立时才本地恢复；零个或多个不同有效结果都进入原有一次模型纠正。
5. 本地恢复保存原始非法参数与解析错误，标记 `locally_recovered=true`，不增加模型调用；成功持久化必须清除旧错误码和错误正文。
6. DeepSeek 文字流读取超时独立设为 30 秒，千问多模态继续使用 600 秒；超时后的传输重试、429 冷却和总调用边界沿用现有规则。

## 结果

- 该机制覆盖缺引号、缺逗号、缺对象或数组闭合、尾逗号和未加引号字段等纯结构错误族，不依赖某个字段或某个错误字符串。
- 结构恢复不能改变模型观点、对象、分类、依据或总结，也不能把 Schema 外枚举、缺失字段、重复字段或前后说明修成有效业务结果。
- 外部服务仍可能发生不可无损恢复的语义违约、内容策略、限流或网络故障；这些继续有界失败并保留证据，不能用伪造结论换取表面失败为零。
- 本决定修正 ADR 0029 中“提供方 Strict Schema 已能约束全部 JSON 结构”的假设；ADR 0029 的模型独立适配、最小合同和后端补齐仍保留。
