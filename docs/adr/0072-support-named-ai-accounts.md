# 支持命名AI账户、按提取入口选用及余额展示

依据用户本轮确认，将单例模型运行配置扩展为多个可命名AI账户，每账户独立维护现有模型、加密连接、并发、判定对象版本与连接可用性。原配置保留为ID=1的默认账户；账户名只负责展示，稳定ID由系统分配，前端通过名称下拉引用。此决定扩展ADR0023单例配置、ADR0028全局并发/冷却以及原“不展示账户余额”的边界。

- 复用sentiment_configs表；旧规则、旧任务默认关联原账户1。新增规则版本保存ai_account_id，手动提交也携带该ID，批次及来源任务冻结ID/名称，分析任务保存实际账户身份，后续修改规则不改变已创建批次。
- 同一节点合并规则时，同一来源的多个开启AI规则若选择不同账户则明确报冲突，不静默择一、不重复采集或付费；AI关闭的规则不参与此冲突判断。不同来源可使用不同账户。
- Worker按任务账户取得凭据、模型与判定对象；连接失效/恢复与429冷却仅作用于相应账户。各账户限制自身并发，进程总并发仍不超过64，本地推理全进程单路。账户变化不成为跨平台帖子结果复用的捷径；自动结果和人工继承按账户与既有内容/版本合同隔离。
- 账户名可修改，API Key仅密文存储，不返回明文；新增账户不复制默认账户的密钥。暂不引入账户删除、充值或支付能力。
- DeepSeek官方账户使用GET /user/balance展示原币种可用/赠金/充值余额；仅按所选已保存账户查询，不向其它域名转发密钥，不猜测兼容代理/千问/本地模型的余额接口。未支持、未配置或查询失败均明确显示状态，不记为0、不改变分析连接状态。
- 按本轮用户明确要求，只交付开发改动，不运行测试、构建、审查或结果验收；未取得质量门证据，不自动推送、合并或部署远端。用户自行查看。

余额协议依据：https://api-docs.deepseek.com/zh-cn/api/get-user-balance/
