# 使用评分页口碑评价篇数替代车型圈子帖子总量

## 背景

原第四数量指标读取车型圈子页“共 N 条内容”。该数字统计圈子帖子，不等于评分页“全部评分”列表的口碑评价文章数，继续沿用会把不同业务对象放在同一口碑指标列中。

懂车帝评分页的服务端状态同时提供两类独立计数：`seriesHomeHead.total_review_count` 对应评价人数，`reviewListData.total_count` 对应“全部评分”的评价文章总数。页面样本证明两者数值可以不同。

## 决定

1. 第四指标命名为“口碑评价篇数”，稳定键为 `review_article_count`。
2. 适配器从当前车型评分页 `__NEXT_DATA__.props.pageProps.reviewListData.total_count` 读取非负整数，来源URL仍是该评分页；不再请求 `/community/{id}`。
3. 评价篇数与页面“共 N 人评价”的口碑量独立保存、比较、着色、汇报并写入XLSX，不互相替代。
4. 旧指标语义不同，不映射为新指标，也不用于首个新批次的比较基线。数据库升级递归清除旧键，并删除含旧列的TXT、XLSX派生产物；正式终态批次按新模板重建。
5. 历史结果没有新指标时显示“历史未采集”，首个新批次显示“暂无基线”，下一自然日才与已冻结的新指标比较。

## 结果

- 口碑详情列与用户看到的“全部评分·共 N 篇”保持同一业务语义。
- 正式巡检减少一次圈子HTTP请求，评价篇数与其他页面指标在同一评分页时点取得。
- 数据清理是有意的不可逆纠正；升级前必须按部署流程备份数据库与口碑派生产物。

本决策替代口碑巡检工作线中2026-08-25采用车型圈子帖子总量的第四指标决定；其他口碑指标、证据和比较合同继续有效。
