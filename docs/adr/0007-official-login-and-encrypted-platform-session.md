# 使用官方登录页面建立加密平台会话

ThreadSnap 第一版和后续正式版均不接收、不保存目标平台账号密码。只有未登录访问不能满足采集要求时，系统才维护一套全局平台会话。浏览器进程、Profile 和最终 Session 均位于部署 ThreadSnap 的服务器上；第一版客户在受控内网客户机的普通浏览器中，通过基础测试界面的临时嵌入式交互入口，查看并操作这台服务器浏览器中的目标平台官方登录页面，自行完成密码、扫码、短信、滑块或其他官方认证步骤。客户机本地浏览器中形成的 Cookie 不会直接交给服务器采集进程，因此该入口不是普通外部登录链接，也不是让客户另开本地浏览器登录。

远程交互通道只传递受控浏览器的画面与输入，不向客户机下发 Cookie、LocalStorage、令牌、Profile 路径或原始 CDP/VNC 地址。第一版通道依赖受控内网边界，使用短期、一次性随机票据绑定当前认证任务，限时、可撤销，不新增应用用户、角色或 MFA；具体浏览器内嵌传输组件需在正式技术栈和目标 Linux 兼容性确认后选择。

公网访问是后续可选部署增强，不属于第一版实现或验收。以后明确需要公网部署时，远程入口必须复用客户现有身份系统和后端权限，并增加敏感操作重新认证、HTTPS/WSS 网关、来源校验、连接限额、审计和 WAF 或等价外围保护；CDP、VNC 或等价浏览器控制端口在任何部署模式下都不得直接暴露公网。

## 自动恢复顺序

1. 正式采集前先用少量真实样本探测当前 Session；
2. HTTP 采集出现 `login`、异常空响应或等价身份异常时，停止发送新请求，持久化当前索引、触发 URL 和待处理队列；
3. 每个失败事件先执行一次有界自动刷新：使用现有加密浏览器 Profile 在服务器打开官方页面并重新导出 Session，随后从触发 URL 继续，由原任务在原 URL 执行采集访问门禁；
4. 如果官方页面出现登录表单、扫码、短信、验证码、滑块或刷新后门禁仍失败，批次转为 `waiting_for_auth`，释放采集 Worker 且不保持数据库长事务；该状态是可恢复的持久化暂停，不是失败终态；
5. 系统为该暂停批次创建限时远程认证入口；用户从暂停批次进入时，首个认证任务直接使用不继承正式 Profile 的空白隔离环境，在客户机上操作服务器浏览器完成官方认证；
6. 用户点击保存且导出的 Session 结构有效后，服务器加密替换 Session，关闭临时远程通道和登录浏览器，并自动将同一批次重新入队，从触发 URL 和既有待处理队列继续；保存操作不判断页面登录状态，真实采集门禁在原 URL 上执行，不要求用户点击“重试批次”；
7. 认证窗口超时或客户机断开时，只关闭临时浏览器控制通道，批次和检查点继续保持 `waiting_for_auth`；用户可以重新打开认证入口，或显式取消该批次。保存后的原 URL 若仍明确要求登录则再次保持等待并记录脱敏原因，不自动循环重登。

自动刷新只复用平台仍认可的既有身份，不等同于自动重新登录。没有验证码也不代表一定可以自动登录；平台已经注销身份且系统不保存密码时，仍需用户在服务器官方页面中操作。`waiting_for_auth` 期间，依赖同一平台 Session 的后续任务继续进入该平台 FIFO 但不得启动采集，其他平台不受影响；Session 保存后先续跑原任务并在原 URL 判断，再按该平台创建顺序处理后续任务，避免同时恢复造成请求突发。

## Consequences

- 配置页面不提供平台账号、密码输入框，也不在数据库中建立平台密码字段。
- 第一版只维护一套全局懂车帝 Session，不实现多账号、账号轮换或配置与账号绑定。
- 持久化范围只包括继续访问所需的 Cookie、LocalStorage、浏览器 Profile 或等价 Session 状态及脱敏元数据。
- Session 与浏览器 Profile 都按敏感凭证处理：必须加密保存，密钥与数据库分离，并限制文件和进程访问权限。
- Session 查询接口只返回是否已保存、已由真实任务判定失效等状态及最近保存时间；“已保存”不表示页面登录或采集访问已验证。批次状态另包含 `waiting_for_auth`。两类接口均不返回 Cookie、LocalStorage、令牌、Profile 路径或原始账号标识。
- 日志、错误、导出、截图、测试报告和 Git 不得包含密码、Cookie 值、动态码、扫码内容或可复用认证数据。
- 管理入口提供“登录/更新会话”和“清除会话”；批次等待认证时还提供“继续认证”和“结束本次提取”。结束操作需要二次确认，并按已有有效结果把批次收口为部分成功或失败，以释放对应平台 FIFO；普通排队中和提取中的批次不提供取消。第一版人工登录入口必须限时、绑定一次性认证任务且只在受控内网可达，并在完成、结束、断开或超时后关闭受控浏览器和远程交互通道，但不得因交互窗口关闭而丢失批次检查点。
- CDP、VNC 或等价浏览器控制端口不得直接暴露给客户机或公网；公网身份认证与外围防护只有在后续明确选择公网部署时才进入实现范围。
- 清除或替换 Session 时应安全删除旧状态；应用停止、异常退出和登录超时不得遗留长期可访问的浏览器控制入口。
- 当前 PoC 使用本地明文配置完成历史测试的事实不迁移为正式实现规范，PoC 产物仍按原证据保留。
