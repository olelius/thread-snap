# 使用官方登录页面建立加密平台会话

ThreadSnap 第一版和后续正式版均不接收、不保存目标平台账号密码。只有未登录访问不能满足采集要求时，系统才维护一套全局平台会话；用户必须在由提取功能服务控制的浏览器中打开目标平台官方登录页面，自行完成密码、扫码、短信、滑块或其他官方认证步骤。普通链接在用户本机浏览器中形成的 Cookie 无法直接交给服务器采集进程，因此“打开官方页面”必须与服务端受控浏览器会话绑定，而不是只提供一个外部链接。

## 自动恢复顺序

1. 正式采集前先用少量真实样本探测当前 Session；
2. HTTP 采集出现 `login`、异常空响应或等价身份异常时，暂停新请求并保留触发 URL；
3. 每个失败事件先执行一次有界自动刷新：使用现有加密浏览器 Profile 打开官方页面；如果官方页面仍保持登录，则重新导出 Session、通过少量门禁后从触发 URL 继续；
4. 如果官方页面出现登录表单、扫码、短信、验证码、滑块或刷新后门禁仍失败，本批次以 `authentication_required` 失败结束，不循环自动登录；
5. 用户通过受控浏览器完成官方认证后建立新 Session，再人工重试失败批次。

自动刷新只复用平台仍认可的既有身份，不等同于自动重新登录。没有验证码也不代表一定可以自动登录；平台已经注销身份且系统不保存密码时，仍需用户在官方页面操作。

## Consequences

- 配置页面不提供平台账号、密码输入框，也不在数据库中建立平台密码字段。
- 第一版只维护一套全局懂车帝 Session，不实现多账号、账号轮换或配置与账号绑定。
- 持久化范围只包括继续访问所需的 Cookie、LocalStorage、浏览器 Profile 或等价 Session 状态及脱敏元数据。
- Session 与浏览器 Profile 都按敏感凭证处理：必须加密保存，密钥与数据库分离，并限制文件和进程访问权限。
- 查询接口只返回 `not_configured`、`valid`、`refreshing`、`authentication_required` 或 `unknown` 等状态及最近验证时间，不返回 Cookie、LocalStorage、令牌、Profile 路径或原始账号标识。
- 日志、错误、导出、截图、测试报告和 Git 不得包含密码、Cookie 值、动态码、扫码内容或可复用认证数据。
- 管理入口提供“登录/更新会话”和“清除会话”；人工登录入口必须限时、仅管理员可达，并在完成或超时后关闭受控浏览器。
- CDP、VNC 或等价浏览器控制端口不得直接暴露到公网；具体远程交互技术在正式前端和部署方案确认时选择，但必须满足现有系统鉴权或本机/受控隧道边界。
- 清除或替换 Session 时应安全删除旧状态；应用停止、异常退出和登录超时不得遗留长期可访问的浏览器控制入口。
- 当前 PoC 使用本地明文配置完成历史测试的事实不迁移为正式实现规范，PoC 产物仍按原证据保留。
