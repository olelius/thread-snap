# 提取功能服务拥有提取数据

ThreadSnap 的提取配置、定时规则、提取批次和提取链接由独立提取功能服务持续拥有和保存。正式系统的现有后端只拥有用户、角色和访问权限，通过仅限本机访问的内部接口调用提取功能服务；这样内部验证版形成的功能闭环可以直接用于正式集成，不需要把提取领域迁移到现有后端数据库。

## Consequences

- 提取功能服务负责提取领域的数据模型、持久化、调度和任务状态。
- 现有后端负责公网接口、身份认证、角色权限和请求授权，不复制提取领域数据。
- 正式前端只调用现有后端，不直接访问提取功能服务。
- 提取功能服务与现有后端部署在同一台主机，内部接口不得监听公网地址。
- 现有后端通过监听 `127.0.0.1` 的版本化 HTTP/JSON 接口调用提取功能服务，内部接口前缀为 `/internal/v1`。
- 内部接口不额外使用共享令牌，依赖回环地址、Linux 进程权限和现有后端的公网访问控制。
- 当前不考虑 Docker 部署，也不绑定某个具体的正式管理框架。

本 ADR 只确定领域所有权与集成边界，不预先确定功能服务使用 Python 还是 Node.js；实现语言由对比 PoC 决定。
