# 正式功能开发前以最简测试包完成 Linux PoC

ThreadSnap 的日常开发环境不是 Linux，而目标部署环境是 Linux。仅在开发环境验证功能或吞吐，不能证明候选方案能够在实际部署环境安装、启动并达到交付门槛。

因此，两个技术栈候选在完成本地访问冒烟和中等批量预筛后，都必须先生成 Linux PoC 测试包，并完成 Linux 部署和目标吞吐验证。只有通过该门禁的候选才可以被选为正式技术路线，之后才开始第一版正式业务功能开发。

这里的“正式功能开发前”不包括 PoC 原型本身。测试包必须基于已经能够运行的候选原型生成，不可能位于所有代码开发之前。

## Decision

- Linux PoC 测试包采用最简单的 `tar.gz` 压缩包，不制作 Docker 镜像、RPM/DEB 包或单文件可执行程序。
- 测试包包含候选原型、锁定的依赖描述、面向目标 Linux 环境生成的离线应用依赖、所需浏览器运行时、Linux 安装脚本、启动脚本、健康检查脚本、统一基准测试入口和简要部署说明。
- 测试包附带版本号和覆盖所有包内产物的 `SHA256SUMS`。
- Python 候选使用面向目标 Linux 生成的 wheelhouse；Node.js 候选使用完整离线包缓存或等价 vendor 目录。包含原生模块时必须在兼容的 Linux 环境生成。
- Windows 的 `.venv`、`node_modules`、浏览器二进制、浏览器缓存和其他机器状态不得复制进 Linux 测试包。
- 凭证、Cookie、令牌、真实配置、历史数据和预置测试结果不得进入测试包。
- Linux 端从干净目录解压，通过包内离线依赖和锁文件重新建立应用运行环境，再执行安装、启动、健康检查、访问样本和三轮目标吞吐测试。
- 依赖稳定性以锁文件、精确版本、测试包版本和 SHA-256 为准；离线副本用于消除测试时上游变化与下载失败，不能替代锁定和兼容性验证。
- Linux 测试机允许联网，但阶段 2.5 和阶段 3 不在线解析或下载应用依赖及浏览器运行时。主机级语言运行时和浏览器系统库可以按已记录版本在线预装。
- Linux 发行版、CPU 架构、libc 和运行时基线确定后才能生成最终离线包，不能直接在 Windows 上下载依赖后假定其可在 Linux 使用。
- 阶段 2.5 和阶段 3 直接在最终部署的 Linux 主机执行，不使用配置相近的临时主机代替。
- 项目负责人手动上传、校验、解压测试包并执行脚本；Codex 不远程登录或自动操作最终主机。
- 人工只负责部署和命令触发，环境快照、测试计时、完成量、访问证明完整率、风控与错误事件和资源指标必须由脚本自动记录。
- `run-poc.sh` 只把本次测试产生的数据写入固定结果目录，不扫描或收集服务器上的其他文件，不采用文件白名单打包方案。
- 每轮测试后由 `run-poc.sh` 在单一轮次目录中生成所有结果文件及 `SHA256SUMS`，作为复核与技术选型证据。
- Linux 测试结束后只把完整轮次结果目录复制回当前开发电脑，不复制程序、离线依赖、运行环境、浏览器目录或数据库。
- 测试结果不执行额外内容脱敏；结果结构和日志从设计上不得包含账号、密码、Cookie 或令牌。
- 原始结果、逐 URL 明细、日志和包含离线依赖的 Linux 测试包只在本地保存，不提交 Git。
- Git 只保留 PoC 汇总报告、技术选型 ADR、必要汇总表和能够关联本地原始结果的 SHA-256。
- 当前开发电脑统一使用 `artifacts/poc/` 保存本地 PoC 产物：测试包位于 `packages/<candidate>/`，各轮结果位于 `results/<candidate>/<round>-<timestamp>/`，不把文件散落到仓库其他路径。
- Linux PoC 测试包和原始测试结果都至少保留到第一版验收完成，之后由项目负责人手动决定继续保留或删除。
- Linux 上发现问题后必须修改候选源码并重新生成测试包，不在测试主机上直接修补后继续计入测试结果。
- 最终主机尚不可用时，Linux 硬门禁保持待执行，不以临时主机结果或估算值代替。

## Consequences

- 跨平台依赖、浏览器运行时、路径、权限、字符编码、时区和进程行为会在正式开发前暴露。
- 两个候选都需要维护一套极简 Linux 安装和运行脚本，会增加少量 PoC 工作量。
- 离线应用依赖会增大测试包体积，也要求在兼容的 Linux 环境执行一次依赖归档。
- 原始证据不进入 Git，需要由项目负责人维护本地存储和备份；仓库中的 SHA-256 用于关联报告与对应的本地证据。
- PoC 产物可以直接作为后续正式部署脚本的依据，但不得未经评审直接视为生产安装方案。
- Linux 发行版、CPU 架构、libc、语言运行时和浏览器系统依赖尚未确认，因此当前只能确定打包规则，不能生成最终可用的离线依赖包。
