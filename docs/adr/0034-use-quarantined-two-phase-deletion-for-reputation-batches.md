# ADR 0034：口碑巡检批次使用同盘隔离的两阶段删除

- 状态：已接受
- 日期：2026-08-24

口碑巡检批次删除会同时影响数据库中的正式批次关联链与文件系统中的指标区域图、预览图、汇报和XLSX。数据库事务不能覆盖文件系统操作，直接交错删除会在任一步骤失败时留下无法判定的半删除状态。删除因此使用持久化清单和同文件系统隔离区：先冻结关联链并生成带校验值的不可变清单，再把全部文件原子移动到隔离区；移动失败按清单恢复文件且不删除领域数据。文件隔离完成后才以单个数据库事务删除关联链并写入唯一墓碑，事务失败时恢复文件。数据库提交是逻辑删除的不可逆边界；提交后的隔离区清理独立重试，失败只表示存储尚未回收，不恢复业务数据。全部阶段使用同一删除作业身份和检查点幂等恢复。

不采用“先删数据库再删文件”，因为文件失败会失去权威引用并遗留孤儿；也不采用“永久删除文件后再提交数据库”，因为数据库失败会留下仍可见但证据已缺失的批次。同盘隔离增加短期磁盘占用和恢复状态，但换取了清晰的提交边界、可审计清单和确定的失败语义。
