# ADR 0005：采用 forged-in-prod 方法控制长期项目流程

status: accepted

## 背景

ThreadSnap 会经历需求澄清、采集器 PoC、Linux 实测、正式开发和后续多平台接入。历史对话或模型上下文压缩不能可靠承担跨任务状态保存；此前的 `current-progress.md` 同时混入当前状态和大量历史结论，也容易与产品设计、技术路线和 ADR 重复。

项目决定参考 `SPHINX998/forged-in-prod` 在提交 `31c80e763541e1526aa9f6ca8692bd344ddff62d` 上定义的七种流程模式。上游采用 MIT License，来源和许可见根目录 `THIRD_PARTY_NOTICES.md`。

## 决策

1. 根目录 `WORKLOG.md` 是唯一活动任务账本；删除 `current-progress.md` 入口，不建立第二份当前进度文档。
2. `AGENTS.md` 常驻任务账本和恢复规则；上下文压缩、新会话或任务恢复后，先读最新账本条目。
3. 跨任务工作线使用 `docs/chains/` 链档维护当前口径、每任务一行的决策链和带解锁条件的未决项。
4. 可复用项目记忆采用“一事一文件”，内容必须包含根因、坑和杠杆；不记录普通提交历史。
5. 验证强度由风险等级决定；代码完成、构建通过或子 Agent 自报通过都不单独构成验收。
6. 多 Agent 只在关闭当前决策门确有净收益时使用；并行写必须用独立 worktree 和唯一文件 owner，主线程负责证据裁决与整合验证。
7. 最终实现采用满足需求的最简单可靠方法，不创建仅为“以后可能用”的页面、配置、抽象、接口或表结构。
8. 长任务先确定当前阶段门、关键路径、写 owner 和验证路径，再决定是否并行。
9. 版本化 `.githooks/pre-commit` 在提交代码时检查 `WORKLOG.md` 是否同步，作为本地兜底；安装脚本只设置 `core.hooksPath`。

## Codex 适配说明

上游 starter 的自动化面向 Claude Code，会写入 `CLAUDE.md`、`.claude/settings.json` 和 Claude `Stop` hook。ThreadSnap 不直接安装这些文件：

- Codex 每轮读取的稳定规则写入 `AGENTS.md`；
- 会话恢复通过 `AGENTS.md` 强制读取 `WORKLOG.md`；
- 当前可验证的自动兜底放在 Git pre-commit，而不是声称存在未验证的 Codex 会话结束 hook。

因此，本决策与上游方法保持一致，但运行时接入点按本项目工具能力替换。Git hook 只能在提交阶段提醒，不能保证在上下文压缩发生前自动写账本；主要约束仍是常驻规则和恢复读取。

## 结果

- 新会话只需读取最新账本条目和任务对应 owner 文档即可恢复，避免重查已有证据。
- 当前状态、主题口径、长期记忆和临时证据有唯一 owner，减少重复和冲突。
- 流程文件数量增加，但每类文件职责固定；不得为了形式完整而为没有真实事故或工作线的内容创建空文档。

## 回退

若该流程产生的维护成本超过收益，应通过新 ADR 替代本决策，并在同一变更中移除 Git hook、更新 `AGENTS.md` 和文档索引、迁移唯一活动账本；不得重新引入多个并行进度文件。
