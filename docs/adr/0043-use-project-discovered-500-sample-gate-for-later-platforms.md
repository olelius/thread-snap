# 后续平台采用项目发现的500条样本验收门禁

## Context

懂车帝阶段曾使用2000条真实帖子验证候选采集框架、平台控制和规模访问，并保留目标CentOS连续三轮门禁。当前Python后端、统一采集器契约、圈子发现、详情处理、持久化、调度、前端和导出闭环已经建立。汽车之家与易车的下一阶段目标是验证各自平台适配器，而不是重新进行通用采集框架选型。

外部配置说明已经提供社区页面入口。最新回复和最新发布入口可从社区页面通过实际点击或等价页面导航取得；易车清单中已经标记为缺失的社区来源属于真实业务缺失。用户同时决定由项目生成验收URL、功能样本、车型映射候选和访问条件证据，并将额外口碑指标来源留到后续处理。

## Decision

1. 汽车之家与易车按平台分别执行一次正式的500条接入验收。每个平台的500条必须是运行前冻结、当前有效、互不重复的帖子详情URL；两个平台不合并分母，也不使用重复URL补量。
2. URL由项目从已确认社区页面取得最新回复和最新发布入口后自动发现、规范化和去重，不再要求甲方为这两个平台另行提供2000条帖子URL清单。
3. 每个平台必须为500条全部产生唯一终态，并满足统一帖子身份、真实内容、必需字段、主评论、媒体、状态和平台控制分类合同；运行时间、资源、请求放大和控制事件继续记录，但不再设置2000条/小时或连续三轮作为新增适配器门禁。
4. 项目从发现池自行生成分层功能样本集，保存可复核的选样规则、场景覆盖和未覆盖项；外部 `functional-samples.csv` 不作为后续平台接入前置。
5. 已确认真实缺失的易车社区来源保持缺失，不生成占位URL、不按名称猜测替代来源，也不阻塞其他已存在来源的适配器验收。对应来源只有在以后取得真实入口并单独验证后才进入配置。
6. 项目负责先验证匿名访问，再按现有官方登录、加密Session、真实样本门禁和有界恢复合同处理确需认证的路径；平台接口、分页、字段和控制行为仍须以当次真实证据确认。
7. 汽车之家与易车的27款口碑车型映射候选由项目依据平台稳定车型身份和页面证据生成，不要求外部提供映射表；候选仍须进入现有草稿、真实验证和显式发布门禁，不按相似名称自动绑定。
8. 汽车之家与易车的口碑评价篇数、差评率及其来源语义暂缓。映射分析可以先行，但在两个指标来源及完整五指标合同验证前，不启用这两个平台的正式口碑巡检，也不把全量分母表述为81。

## Scope and compatibility

- 本决策只适用于懂车帝之后新增的汽车之家与易车适配器验收。
- ADR 0004、0006和0011中懂车帝采集框架、既有2000条证据及目标CentOS门禁保持有效；500条门禁不构成对它们的替代或降级。
- 500条通过证明的是对应平台、适配器版本、冻结样本、访问模式、网络、环境和测试时点下的接入正确性，不形成对平台未来变化或更高吞吐的永久推断。

## Consequences

- 后续平台不再重复收集与框架选型阶段相同规模的外部输入，接入成本集中在平台特有发现、详情、评论、状态和访问条件。
- 项目必须保存来源清单、冻结样本、哈希、逐URL结果、功能样本清单和汇总证据，500条验收仍是可审计的真实运行，而不是抽样演示。
- 真实缺失来源和延期口碑指标会作为明确边界保留；它们不被占位数据掩盖，也不被误报为已接入。
