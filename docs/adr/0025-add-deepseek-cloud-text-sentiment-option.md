# ADR 0025：增加 DeepSeek 云端纯文字舆情选项

- 状态：已接受
- 日期：2026-08-21

## 背景

现有千问 Omni Plus 路径能够处理文字、图片、视频画面和音频，但部分场景只需要云端模型分析标题和正文。DeepSeek 提供 OpenAI 兼容 Chat Completions、流式响应和 JSON Object 输出，可以复用 ThreadSnap 的窄客户端、持久队列和统一舆情结果合同；其当前聊天接口只接收文字消息，不能沿用千问的图片和视频请求体。

## 决定

1. 受控模型下拉新增 `deepseek-v4-flash`，界面名称为“DeepSeek V4 Flash（云端文字）”。
2. DeepSeek 每帖只接收舆情判定对象、完整标题和完整正文，不接收图片/视频 URL、稳定哈希或媒体内容；评论仍不参与。请求固定关闭 thinking，使用 JSON Object、流式响应和流式用量。
3. DeepSeek 原生 JSON 提供对象相关性、情感、类型、中文总结和文字依据。后端依据“媒体没有发送”这一确定事实，把实际图片/视频数量补为 `not_requested`，不改写模型观点字段。
4. 千问与 DeepSeek 分别保存独立的加密 Base URL/API Key；API 只返回各连接是否已配置和脱敏地址，不返回密钥明文。切换模型使当前验证失效，但不覆盖另一提供方连接。
5. DeepSeek 复用两个云端消费者、SSRF/重定向防护、显式连接测试、截断审计、有界重试、人工修正和统一结果筛选；不增加新的 Worker、余额查询、自由模型名或通用模型平台。
6. DeepSeek 输入指纹只包含标题和正文，媒体 URL 变化不影响同一文字输入的精确复用；详情媒体展示继续独立工作。

## 结果

- 需要云端中文语境理解但不需要媒体分析时，可以避开视频地址刷新和多模态输入开销。
- OpenAI 兼容只复用传输协议，不把不同提供方输入能力视为相同；千问和 DeepSeek 使用各自的请求构造。
- 数据库新增 DeepSeek 独立连接字段并保留旧千问字段，迁移回退只删除新增槽，不改变已有千问配置。
- 该决定扩展 ADR 0022、0023 和 0024，不替代千问多模态或本地轻量路径。
