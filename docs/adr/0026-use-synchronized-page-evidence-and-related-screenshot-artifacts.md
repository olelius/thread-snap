# ADR 0026：使用同步页面证据生成关联圈子截图成果

- 状态：已接受
- 日期：2026-08-22

## 背景

圈子列表会随新回复和发布持续重排。若 HTTP 采集器与浏览器截图各自发现列表，即使并行且时间接近，也可能取得不同帖子、顺序或页面内容；若事后重新打开页面补拍，也不能代表原批次采集时刻。另一方面，手动补提会在不同批次补齐同一来源，人工修正又会改变当前有效舆情结论，截图成果既需要保留原始证据，又需要随当前关联结果生成新版本。

## 决定

1. 所有实际执行的圈子发现任务强制同步冻结页面清单和物理分页原始证据；截图与详情采集共同使用这一清单，不各自重新发现列表。URL 清单和未执行来源不生成圈子截图成果。
2. 页面捕获成为列表身份、顺序和卡片位置的事实来源；每冻结一页即可在平台资源预算内流水线并发详情采集。卡片文字、媒体和布局未完整稳定时证据失败，原始证据只在当次页面上下文内重试，事后恢复创建新关联采集。
3. 原始分页证据不可变。最终成果从原始证据裁取实际入库且可追溯的帖子卡片，直接复用现有有效舆情结论，以整卡红框表示负面，不增加 OCR 或第二套舆情判定。
4. 原批次及全部补提批次中的同一实际来源使用独立稳定的关联成果组。当前成果按跨补提稳定去重与顺序合并，明确标注贡献批次和采集时间；补提、删除或有效舆情变化生成新版本，前端只暴露唯一当前版本，历史版本保留审计。
5. 只有当前关联结果全部证据化帖子具有有效舆情结论时才产生最终成果。零负面生成无红框成果，平台明确空列表生成零结果成果，错误导致零条不生成最终成果。提取、舆情和成果状态分别持久化。
6. 一个关联成果在正常尺寸下使用单张无损 PNG，超过经真实基准验证的边界时按完整卡片无损分片；业务仍只有一个逻辑成果，前端连续展示并以一个成果包下载，不降低每圈 2000 条采集上限。
7. 页面截图成果留在现有批次详情的“页面截图”标签，不新增顶级导航或第二份批次列表。历史批次不补拍；截图证据与批次同寿命、进入备份、不自动过期，并按贡献批次和成果组引用关系清理。

## 结果

- 帖子与截图的一致性由同一有序页面清单证明，不依赖无法复核的时间差。
- 原始证据保持单时点真实性，跨批次最终成果明确作为派生版本，不冒充平台原始页面。
- 当前成果可以跟随补提、删除和人工修正更新，同时保留历史版本与文件哈希。
- 浏览器捕获、数据库迁移、超长分片、持久文件和备份进入高风险验证范围；实现前必须通过真实最新回复、最新发布、跨页、补提和目标 Linux 分片 PoC。

该决定扩展 ADR 0009、0017、0018、0019 和 0022，不改变提取批次不可变、舆情结论优先级或单后端部署边界。
