# ADR 0067：批次首轮完成后统一复访来源级瞬时失败

- 状态：已接受
- 日期：2026-09-03
- 关联：`src/threadsnap/worker.py`、`src/threadsnap/services.py`、`docs/design/product-design.md`

## 背景

开启页面证据时，平台页面可能已经返回正常文档，但列表脚本偶发没有发出可绑定当前来源的官方列表响应。原实现把这类来源级异常直接落为任务失败，容易把一次性页面加载波动表现为最终失败。

## 决定

1. `PAGE_EVIDENCE_LIST_RESPONSE_MISSING` 归类为来源级可恢复错误，不在首轮结束时直接形成终态。
2. Worker 先完成同一批次各平台的首轮来源；首轮仍在进行时，带 `batch_retry_wave` 标记的来源保持队列等待，不阻塞同批次其他来源。
3. 首轮所有来源进入终态后，统一复访标记来源一次，使用新的采集器/页面上下文并沿用原来源 URL、固定候选和平台 FIFO。
4. 复访成功时清除临时错误并按正常结果汇总；复访仍缺少列表响应时才写入来源失败。网络错误、限流和认证恢复继续使用既有即时退避、冷却和会话状态机。
5. 批次在统一复访期间保持 `running`，前端可显示“首轮完成，统一重试中”；来源失败数与单帖失败数分开统计。

## 未采用方案

- 对所有来源立即重试：会让某个平台的瞬时异常占用当前平台通道，且多个平台的重试时间点不可控。
- 把缺少列表响应当作成功：会失去页面证据与帖子身份绑定，破坏固定候选合同。
- 创建新批次重试：会改变批次快照和不可变历史，统一复访应留在原任务内。
