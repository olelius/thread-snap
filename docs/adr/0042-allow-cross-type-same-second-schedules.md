# 允许每周与循环计划同秒创建独立批次

每周计划与循环计划是两种独立业务类别。启用节点的实际触发键调整为 `(node_type, weekday, HH:mm:ss)`：两个每周节点或两个循环节点命中同一类型键时，整份配置零写入并返回全部冲突位置；每周节点与循环节点命中同一秒时允许共同保存。

跨类型同秒到期时，全局调度器分别创建一个 `scheduled` 定时批次和一个 `recurring` 循环批次。两个批次各自冻结节点引用的规则版本、来源、参数和运行配置，使用各自“节点 + 计划时刻”幂等键，不跨节点合并、覆盖或去重。为消除节点 ID 排序造成的偶然行为，同秒时每周批次先于循环批次入队；这只是稳定入队顺序，不赋予抢占能力，同一平台继续按既有 FIFO 顺序执行。

调度器在运行期重新展开全部启用节点。异常持久数据若形成同类型同秒冲突，则为每个冲突节点记录 `blocked` 调度事件，并跳过该组全部批次；跨类型同秒不属于异常，继续分别触发。停用节点仍可以暂存同类型冲突，重新启用时必须通过保存校验；服务停机错过的帖子提取触发点仍不补跑。

本决策替代 ADR 0013、0015、0016 与 ADR 0040 中“所有计划类型之间实际触发秒全局唯一”的部分。上述 ADR 关于节点与规则职责分离、规则版本、节点内多规则合并、循环时间展开、配置 revision、平台 FIFO 和历史批次快照的其余决策继续有效。
