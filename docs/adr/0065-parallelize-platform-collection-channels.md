# ADR 0065：普通帖子提取启用三平台并行通道

- 状态：已接受
- 日期：2026-09-03
- 关联：`src/threadsnap/worker.py`、`src/threadsnap/config.py`、`docs/design/product-design.md`、`docs/design/technical-route.md`

## 背景

普通帖子批次已经可以包含多个平台来源，但原 Worker 每轮只领取一个平台队首，平台级并发固定为 1。三个平台内部并发分别由平台配置控制，跨平台串行使同一批次的等待时间被平台顺序叠加。

## 决定

1. 保留一个持久 Worker 进程和一个全局调度源，在 Worker 内建立最多三个平台执行通道；当前默认平台级并发为 3，服务端配置范围为 1～3。
2. 每个平台通道独立调用既有平台 FIFO 队首处理流程；同一平台同时只运行一个队首批次，手动、定时和补提仍保持同一平台严格 FIFO。
3. 每个平台通道在线程内创建自己的 Collector 和 Scrapling `FetcherSession`，不在线程之间共享平台 Session 或浏览器上下文；平台内部并发继续使用批次快照和平台安全上下限。
4. 认证等待、限流冷却、重试检查点和恢复状态按平台隔离；某一平台暂停时释放其通道，其他平台继续处理。
5. 口碑巡检固定内部并发 2 的业务合同保持独立，不随普通帖子提取的平台级并发改变。

## 影响与验证边界

- 三平台同时运行时，当前平台内部配置理论上会叠加为汽车之家 1、懂车帝 8、易车 1；组合吞吐、CPU、内存、429、验证码和 SQLite 写入压力需要按真实环境继续观测。
- 平台级并发属于后端运行配置，客户前端不直接编辑；降低到 1 可恢复原平台串行行为。
- 回归测试使用三个同步屏障验证同一 `process_once` 轮次同时进入三个可用平台队首；既有后端全量测试继续验证任务状态、认证恢复、限流和 FIFO 语义。

## 未采用方案

- 直接启动三个完整 Worker 进程：会重复实现领取、恢复和批次汇总，并增加 SQLite 多进程协调与全局容量控制复杂度。
- 共享一个 Collector 跨平台执行：平台 Session、传输池和浏览器上下文边界不同，线程共享会破坏隔离合同。
