# 增加按时间段和分钟间隔触发的循环计划节点

帖子提取在既有“每周计划”之外增加“循环计划”。循环计划节点仍只保存星期、启用状态和一条或多条自动提取规则引用，时间部分改为同一自然日内的开始时刻、结束时刻和正整数分钟间隔。实际触发点按 `开始时刻 + n × 间隔分钟` 展开：开始时刻始终触发；不超过结束时刻的点均触发；结束时刻只有在该序列恰好命中时才触发。开始时刻必须早于结束时刻，第一版不跨午夜，间隔范围为 1 到 1440 分钟。

循环计划与每周计划复用同一 `schedule_nodes` 持久对象、节点—规则关联、全局调度线程、配置 revision、`/extraction-plan` 保存事务、规则引用保护、批次快照和“节点 + 计划触发时刻”幂等键。节点以类型区分：每周节点使用单一时刻，循环节点使用开始、结束和间隔；API 分别返回 `nodes` 与 `recurring_nodes`，便于两个配置标签独立维护草稿，同时仍由一次事务做组合校验。

循环节点创建的提取批次使用独立触发类型 `recurring`，每周节点继续使用 `scheduled`，因此批次列表和详情摘要可以明确区分“循环计划”与“定时提取”。两类批次仍复用同一个列表和详情组件、字段结构、状态机、圈子任务、进度、认证、重试、导出与删除能力；不为循环批次复制第二套业务流程。循环批次的具体导航与列表路由安排由 ADR 0041 替代。

全部启用节点先展开为实际 `(weekday, HH:mm:ss)` 触发键，再执行全局唯一校验。每周与循环节点、两个循环节点只要在同一秒实际相交，整份配置零写入并返回全部冲突节点；仅时间段重叠但触发序列不相交不算冲突。停用节点允许暂存冲突，重新启用时必须通过同一校验。调度器继续只检查相邻轮询窗口，服务停机错过的循环触发点不补跑。

前端在配置管理中新增与“每周计划”并列的“循环计划”标签。它复用每周计划的工具栏、节点卡片、星期按钮、启用开关、规则多选、字段级未保存标识、放弃修改和保存反馈；唯一的结构差异是把单一时刻替换为带可见标签的开始时刻、结束时刻和间隔分钟输入。两个标签各自保存时保留另一标签的服务器基线或本地草稿，不通过新增端点复制规则或调度逻辑。

本决策扩展 ADR 0009、0013 和 0016；这些决策关于全局调度、平台 FIFO、规则版本、一次触发一个合并批次和历史快照的其余边界继续有效。
