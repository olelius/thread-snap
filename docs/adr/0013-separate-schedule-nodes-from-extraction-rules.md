# 每周计划节点引用可复用自动提取规则

定时提取不再把时间与数量等参数塞进同一条重复配置，也不继续由平台配置持有自动每圈数量。每周计划节点只描述星期、时刻、启用状态和规则引用；带名称的自动提取规则集中持有定时提取业务参数并可被多个节点复用，但不选择平台、车型或圈子。平台配置只拥有接入、并发、启用和 Session，车型与圈子只拥有来源资料、验证与自动参与资格；规则触发时作用于全部符合这两层资格的来源。其他页面可以引用或只读展示，但不提供重复编辑入口。该边界减少星期五、周末等多时段策略产生的参数副本，并要求初始数据库基线、页面 API、集成 API、调度幂等键与批次快照使用同一模型。

规则以稳定逻辑 ID 和不可变版本保存：修改只影响未来触发，批次冻结确切版本；任何计划节点引用都会阻止规则归档或删除。解除全部引用后，从未形成批次快照的规则可以永久删除，已有历史使用的规则只归档并允许恢复，从而同时避免失效引用和历史解释漂移。

由于第一版规则作用于全部自动提取来源，所有启用节点按逐日展开的“星期 + `HH:mm:ss`”保持全局唯一。停用节点可以暂存重叠，但启用时重新校验；冲突不自动合并或按顺序覆盖，避免相同来源在同一时刻被不同规则重复创建批次。

第一版尚未正式交付且仓库内没有需保留的业务数据库，因此直接采用全新数据库基线，不转换旧 `times` 或平台自动数量，也不自动生成默认规则；首次使用由用户创建规则和节点。正式交付产生持久数据后的结构变化再通过新增迁移处理。

后续新平台接入后默认停用；平台启用只校验启用节点所引用规则是否已填写该平台数量，缺失数量仍回到提取计划编辑。节点启用时校验其规则覆盖全部已启用平台，调度触发保留相同防御门禁并在缺失时停止整个节点触发，从而不靠静默跳过平台掩盖跨页面配置缺口。
