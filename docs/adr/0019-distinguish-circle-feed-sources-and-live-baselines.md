# 区分同圈列表来源并以服务器版本更新清洁草稿

> ADR 0020 已替代本 ADR 的模板标签格式：第一版正式数据在交付前清理，现只接受 `source.<source_key>.<field>`，不保留来源 UUID 长标签兼容分支。

Status: accepted

## Context

同一个懂车帝圈子同时存在“最新回复”和“最新发布”两个动态列表。旧模型只用平台代码和平台圈子 ID 判重，并把 `/community/<id>` 固定解释为最新回复，因此无法同时保存两个来源，批次列表又只显示平台返回圈子名称，用户无法分辨来源。配置页还会在 SSE 刷新服务器提取计划后，用新服务器数据直接反向比较旧本地副本，把没有本地操作的服务器变化误标成“未保存”。

## Decision

1. 平台圈子来源的稳定身份改为“平台代码 + 平台圈子 ID + 版块 + 列表顺序”；`latest_reply` 和 `latest_publish` 是两个独立来源配置 ID。
2. 懂车帝规范化链接分别使用 `/community/<id>` 和 `/community/<id>/dongtai-release`；分页在对应规范化链接后附加页码。校验必须真实访问用户选择的列表，不把两个入口归并成同一个来源。
3. 用户编辑字段在界面称为“来源名称”。批次、任务和结果优先显示创建任务时冻结的来源名称，同时保留平台返回圈子名称用于平台身份和诊断。
4. 自动提取规则继续保存来源配置 ID；多规则去重也按来源配置 ID 判断。同一平台圈子不同列表顺序是两条来源，分别提交时形成独立批次，不因平台圈子 ID 相同而覆盖或归并结果。
5. 配置 SSE 到达时，前端以“旧服务器基线”判断是否存在真实本地编辑：清洁部分直接采用新服务器版本；有本地草稿的部分继续保留并依赖 revision 冲突阻止覆盖。
6. 历史 `vehicle`/`vehicle_name` API、数据库字段和 XLSX 字段作为兼容名保留，不再作为用户界面的领域术语。
7. 新生成的 XLSX 标签使用来源配置 ID：`platform.<platform_code>.source.<source_id>.<field>`；新增 `source.id`、`source.name`、`source.list_order` 和 `source.list_order_name` 字段；旧 `circle.<circle_id>` 标签继续读取，避免已有模板失效。

## Consequences

- 现有圈子来源迁移为 `latest_reply`，历史批次保持原快照和顺序。
- 来源格式、数据库唯一约束、手动输入去重、验证、任务快照、规则选择和批次展示必须使用同一列表顺序语义。
- 平台返回圈子名称可能重复，这是正常事实；用户来源名称负责业务区分，但不承担稳定寻址。
