# ADR 0070：易车口碑临时采用 URL 模式并停用截图

- 状态：已接受
- 日期：2026-09-07
- 依据：用户明确要求易车暂时切回 URL 处理、不截图，不再把原生 Runtime 前置条件作为当前采集错误。
- 替代：ADR 0064、0068 中对易车本阶段截图的硬要求；原生 Runtime 研究与历史证据保留。

## 决策

1. 易车口碑适配器固定为 `yiche-reputation-url-v2`，使用已验证的点评 URL 在后台读取真实页面与响应，不调用 ADB、Android Runtime 或截图API。已有共享 Session 可复用，无 Session 时允许页面自行给出可访问性结果。
2. URL/车型身份校验仍执行；未提供的评分、排名、数量保存空值，点评总数0保持合法零值。真正的页面访问、身份或接口错误仍明确报告，不以成功掩盖失败。
3. 平台声明 `requires_evidence=false`；正式执行、失败项补跑、映射验证及验证成果转基线均遵循该策略。27车型×3平台仍为81个执行项，但本阶段正常截图分母为54（懂车帝/汽车之家），易车不生成空白PNG或虚假证据。
4. 每个执行项继续持久化实际 `evidence_required`；终态历史批次、原始错误、既有PNG/XML、报告与比较基线不改写。切换前的原生错误在默认排名表中显示“历史失败/旧流程”，完整原因按需打开；新结果只能来自新批次或关联补跑。
5. 旧Web/原生映射合同继续按映射哈希验证，不因运行方式切换要求重新创建车型和URL。后续恢复原生截图须明确决定并完成可用 Runtime、真实页面身份与截图验证，届时只影响后续执行。

## 验证和回退

- 覆盖URL样本真实访问、无截图、空指标和零数量、身份不符、混合平台81项/54证据、映射验证与基线、关联补跑。
- `reputation_registry.py` 是平台模式唯一归属；回退需恢复对应适配器及证据策略，不删除历史数据。
