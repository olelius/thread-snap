# ADR 0070：易车口碑临时采用 URL 模式并停用截图

- 状态：已接受
- 日期：2026-09-07
- 依据：用户明确要求易车暂时切回 URL 处理、不截图，不再把原生 Runtime 前置条件作为当前采集错误。
- 替代：ADR 0064、0068 中对易车本阶段截图的硬要求；原生 Runtime 研究与历史证据保留。

## 决策

1. 易车口碑适配器固定为 `yiche-reputation-url-v3-mobile-metrics`，使用已验证的点评 URL 在后台读取车型身份、口碑分和参与人数，并通过APK已确认的移动端接口读取热门对比评分排名与车主点评数；不调用 ADB、Android Runtime 或截图API。已有共享 Session 可复用，无 Session 时允许页面自行给出可访问性结果。
2. URL/车型身份校验仍执行。排名从 `app_review/api/v1/review/serial_rating_sort` 的有序 `serialList` 按稳定 `serialId` 匹配；参与人数沿用点评页 `authorCount`；车主点评从 `app_review/api/v1/review/overview_review_list` 的 `ratingCard.topicCount` 读取。易车不再展示“口碑量”和“口碑评价篇数”：既有 `volume` 存储槽在易车显示为“参与人数”，新 `owner_review_count` 独立显示为“车主点评”，旧 `review_article_count` 不进入易车能力集合。未提供的单项保存空值，零值保持合法；真正的页面访问或身份错误仍明确报告。
3. 平台声明 `requires_evidence=false`；正式执行、失败项补跑、映射验证及验证成果转基线均遵循该策略。27车型×3平台仍为81个执行项，但本阶段正常截图分母为54（懂车帝/汽车之家），易车不生成空白PNG或虚假证据。
4. 每个执行项继续持久化实际 `evidence_required`；终态历史批次、原始错误、既有PNG/XML、报告与比较基线不改写。切换前的原生错误在默认排名表中显示“历史失败/旧流程”，完整原因按需打开；新结果只能来自新批次或关联补跑。
5. URL/车型映射继续按映射哈希验证，不因指标来源调整要求重新创建车型；排名及数量合同升级为 `yiche-reputation-mapping-v2`，旧验证需要按新合同重新验证，历史结果不回填或跨语义比较。后续恢复原生截图须明确决定并完成可用 Runtime、真实页面身份与截图验证，届时只影响后续执行。

## 验证和回退

- 覆盖URL样本真实访问、热门对比榜原始顺序、目标缺席、参与人数与车主点评独立字段、无截图、空指标和零数量、身份不符、混合平台81项/54证据、映射验证与基线、关联补跑。
- `reputation_registry.py` 是平台模式唯一归属；回退需恢复对应适配器及证据策略，不删除历史数据。
