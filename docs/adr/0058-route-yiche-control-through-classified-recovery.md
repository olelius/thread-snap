# 易车平台控制按真实类别进入恢复状态机

## Context

易车原适配器会把详情页 `203` 挑战后紧接的 `403` 统一解释为登录失效，把腾讯 WAF
控制文档抛成 `AUTH_REQUIRED`，并把接口 `429` 记为未被 Worker 冷却状态机识别的
`RATE_LIMITED`。这些分类会让仍可用的账号 Session 打开空白登录环境，也会让应当停止
并发请求的控制错误被圈子采集器吞成普通候选失败。

2026-09-01 的真实并发8轮次 `20260901-154036-001` 使用8个来源、每来源30条、同批次
冻结240条目标。该轮取得59条不同结果后，8个来源全部停止；停止后的账号身份接口和三个
列表接口仍为HTTP 200，详情序列为 `203 -> 403`。约5分43秒后使用同一Session、并发1
复访，账号和列表仍为200，详情恢复为 `203 -> 200`，评论接口为200并取得1条有效结果。
脱敏回执为 `artifacts/runtime/yiche-concurrency-20260901/acceptance.json`，SHA-256为
`86a80da1fefc038ea33c23675393c016a73568b6e7530fa3436e57be826bef5f`。

该证据确认并发8没有完成目标，且控制发生时不是账号整体退出；它与详情请求突发触发的短期
访问控制一致。后续独立冻结1000个不同详情URL并使用实际并发1的批次
`20260901-164445-001`，在完成数59、118、840、897、954观察到5次腾讯验证码，并在118到840
之间观察到7次详情页面HTTP 429冷却边界；同一原任务最终完成1000/1000、失败0。输入SHA-256为
`e8a5437938d85baeefd626b82bfe541e3983bd72353072abb4e4f59ef8570d67`。

对照同时证明：验证码期间账号身份和列表API仍可用；生产长会话处于429冷却时，同出口的新HTTP
会话在空Cookie、设备Cookie、账号Cookie和完整Session下均可取得正文，因此429不是账号或全局
IP封禁。验证码发生时，同出口、同保存Session的全新HTTP传输仍取得WAF验证码，说明验证码状态
跨越单一旧连接；第3、4、5次验证码都在约13分钟静默后由同IP、同账号、同Profile和同触发URL
零交互恢复正文，后两个无并行探针干扰的周期均新增57条再次触发。最符合全部证据的是详情路由
按高请求速率累积、随时间衰减，并叠加出口IP、浏览器/Profile和WAF清除状态的复合风险桶。并发1
只串行而没有节流，不能作为免控阈值；约13分钟和57～59条只是本轮观测值，不是平台精确TTL或
固定阈值。脱敏根因报告SHA-256为
`3737de8252999f97d1c7a9a4b577181d8d4fa26df78100997ff334486a35d800`。当前证据仍没有确定1到8
之间的稳定安全阈值，也没有证明并发2或4在多轮运行中稳定。

## Decision

- 账号门禁或普通详情请求直接返回401，以及没有203前置证据的普通403，继续分类为
  `AUTH_REQUIRED`并使用既有登录恢复入口。
- 详情严格解析一次已知203挑战并复访同一URL；复访403分类为`PLATFORM_CHALLENGE`，
  保存原触发URL并进入共享`waiting_for_auth`。
- TencentCaptcha/WAF文档继续先使用ADR 0055的一次有界Stealthy恢复；原URL复访仍为
  控制文档时分类为`PLATFORM_CAPTCHA_REQUIRED`，复访403时分类为
  `PLATFORM_CHALLENGE`。两者都继承当前加密Profile并打开原触发URL，不清除登录态。
- 页面或API返回429统一分类为`PLATFORM_RATE_LIMITED`，交给Worker现有固定URL、递增
  冷却、单来源并发1的自动续跑状态机，不进入认证窗口。
- 以上三种平台控制一经候选详情或URL采集观察到，立即中断当前采集器调用并交回Worker；
  不把它们累计为普通候选失败，也不继续请求同一来源的其他固定URL。
- 人工完成访问验证并保存Session后复用现有通用恢复：每批次只释放最早等待来源作为实际
  并发1的原URL探针，探针形成终态后才释放同批次其他来源并恢复冻结并发。
- URL清单任务的恢复探针从原冻结清单扣除已经持久化的帖子ID，只访问未完成URL，并沿用
  原清单位置；控制发生前的成功项不从清单开头重复请求。
- 易车配置范围暂时保留1～8，但本轮后当前运行配置恢复为1。提高并发需要新的固定输入、
  独立多轮证据；本决策不把未验证的2或4声明为安全值。

本决策细化ADR 0047的易车直连响应分类，并补充ADR 0055中易车Stealthy失败后的持久恢复
路径；不改变普通无控制请求仍使用Scrapling FetcherSession的决定。

## Consequences

- 易车适配器升级为`yiche-community-v7-control-recovery`。
- 真实账号退出与详情访问控制在错误码、Profile继承方式和打开URL上保持不同，避免把可用
  Session清空后要求重新登录。
- 挑战或验证码出现后，同批次已完成结果、固定候选和任务检查点保持不变；恢复不创建替代批次。
- 限流冷却由Worker持久化并在服务重启后继续，接口429不再降级为普通字段失败。
- 不新增数据库字段、Session格式、前端页面、验证码识别能力或隐式请求重试。
- 后续腾讯 WAF 逆向调研按 `docs/research/yiche-tencent-waf-reverse-runbook.md` 隔离执行，复用本决策的控制分类和止损证据；MCP或视频流程出现时本决策仍保持有效，生产行为变化需要新的设计证据和ADR。
- 2026-09-02 的 ADR 0060 已用新的设计证据接受共享腾讯纯协议组件，并替代本决策中“验证码先尝试Stealthy”的分支；本决策继续管理自动链失败后的`waiting_for_auth`以及账号失效、详情挑战和限流分类。
- 2026-09-02 的 ADR 0061 已在易车首次429分类前增加一次当前线程HTTP传输轮换；新传输
  仍为429时继续进入本决策与ADR 0052定义的持久冷却。

## Rejected alternatives

- **把所有403继续解释为登录失效**：真实轮次中账号身份与列表接口同时可用，不能支持该结论。
- **控制出现后继续处理同来源其他候选**：会在已经观察到控制时扩大请求突发并污染失败统计。
- **把并发上限固定为1并视为免控方案**：固定1000条诊断已经证明并发1仍会触发验证码；当前
  配置保持1只能限制请求突发，不能替代控制分类、止损和原任务恢复。
- **Stealthy页面HTTP 200即视为恢复成功**：验证码文档本身也可返回200，仍须由原业务请求和
  既有内容合同确认。
