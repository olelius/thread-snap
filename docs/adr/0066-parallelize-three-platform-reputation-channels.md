# ADR 0066：口碑巡检三平台同时进入执行

- 状态：已接受
- 日期：2026-09-03
- 关联：`src/threadsnap/reputation.py`、`src/threadsnap/reputation_browser.py`、`src/threadsnap/reputation_dongchedi.py`、`docs/adr/0064-register-autohome-and-yiche-reputation-adapters.md`

## 背景

完整三平台口碑批次包含多个平台的车型执行项。原实现按平台注册顺序逐个平台调用适配器，虽然适配器内部有并发，但汽车之家、懂车帝和易车的启动时间被平台顺序串联。

## 决定

1. 一个口碑批次为每个平台创建独立执行通道，三个通道在同一批次中同时进入适配器执行。
2. 保留既有 `REPUTATION_RUN_CONCURRENCY = 2` 业务规则。所有平台通道共享一个跨线程信号量，浏览器访问、稳定测量、截图和即时重试在任何时刻合计最多两个活动槽位。
3. 共享槽位通过适配器内部的异步任务边界取得和释放；汽车之家、易车共用浏览器骨架，懂车帝的HTTP优先和浏览器证据路径均接入同一跨平台限制。
4. 每个平台继续使用独立 Session、适配器实例、输出目录、重试流程和逐项持久化。平台顺序只用于冻结目标、汇报和导出展示，不再决定实际启动先后。
5. 口碑巡检与普通帖子提取的并发配置继续隔离；普通帖子平台级并发变化不改写口碑巡检的固定总并发2。

## 影响与验证边界

- 三个平台的适配器线程可以同时启动，但实际页面活动总量仍为2，保持既有浏览器资源和平台负载合同。
- 单个平台认证或异常只影响该平台的执行项，其他通道继续处理；最终批次仍按全部车型×平台项汇总。
- 三平台完整回归使用同步屏障确认三个平台通道同时进入 `validate_sync`；既有25项口碑测试和完整后端质量门继续覆盖结果、证据、重试和汇报。

## 未采用方案

- 把每个平台并发2直接相加为全局6：会改变已接受的巡检内部并发2，并扩大浏览器与平台控制风险。
- 启动三个独立口碑 Worker 进程：会重复批次状态和报告逻辑，且需要额外的跨进程信号量与数据库协调。
