# 舆情反馈使用在线多模态 API 和异步持久任务

## Context

新增需求需要针对帖子完整正文、图片和视频给出品牌立场下的情感倾向、负面类型和判断依据，并允许人工随机复核。当前 ThreadSnap 只保存媒体 URL，数据库中 842 个不同帖子没有视频样本；本地部署小模型能否同时理解完整视频画面和音频尚无证据。该能力也不需要多轮对话、检索或工具规划，因此“智能体”不是必要架构。

用户要求优先由模型服务直接读取媒体 URL，避免 ThreadSnap 下载视频占用带宽、磁盘和转码资源；同时要求系统忠实保存模型的实际反馈，不以人工标注、召回率或漏判上限充当模型反馈的真实性门禁。

## Decision

1. 第一轮 PoC 使用阿里云百炼 OpenAI 兼容 Chat Completions API 和固定模型快照 `qwen3.5-omni-plus-2026-03-15`。每条帖子使用一次非流式多模态请求完成情感、类型、模态覆盖和依据输出。
2. ThreadSnap 把完整标题、正文、全部图片 URL 和全部视频 URL 直接提交给模型服务；评论不进入输入。ThreadSnap 不下载、中转、转码、抽帧或语音转写媒体，PoC 按模型官方限制原样验证 URL 可访问性和视频画面/音频覆盖。
3. 该能力作为同一 Python 应用进程内的独立持久任务和后台 Worker 实现。提取事务只负责可靠入队，分析状态与提取状态分离；不新增 Agent 框架、RAG、第二模型、Redis、Celery 或微服务。
4. 后端保留模型原始响应和规范化字段，只校验 JSON Schema 与模态覆盖，不自行重判模型结论。完整 AI 反馈默认生效；部分结果保留但不生效；人工修正优先且以追加记录保存。
5. 同帖内容未实质变化时可继承人工判定；无人工结果时，仅在帖子身份、输入指纹、判定对象版本、提示词版本和模型快照完全一致时复用完整 AI 结果。任何复用都引用原结果，不改写历史快照。
6. 正式实现前先取得至少 30 条真实视频帖子执行事实型 PoC。报告媒体 URL 获取、视觉/音频覆盖、结构有效性、耗时、用量、成本与失败分布；不设置准确率、召回率、误判率、漏判上限或人工一致性阈值。

## Consequences

- 第一阶段只需一个窄接口模型客户端和现有应用内持久 Worker，运行与部署复杂度低于本地模型或智能体平台。
- 视频 URL 的可达性、防盗链、签名过期和提供方限制成为必须用真实样本量化的外部依赖；出现失败时先记录分布，再决定是否新增媒体中转方案。
- 外部服务会接收帖子正文和媒体 URL；API Key、平台 Session、Cookie、账号凭证和签名 URL 查询不得进入前端、Git 或明文日志。
- 结果目标是可追溯地忠实呈现单一模型反馈，而不是证明模型具有客观正确率；业务使用者仍可随机复核并覆盖有效结论。
