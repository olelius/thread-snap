# 分离采集框架访问 PoC 与第一版功能验收

## Context

第一版最终需要同时支持圈子列表自动发现和已知帖子 URL 清单导入，并完成正文、最多十条主评论、批次存储、前端和导出闭环。

当前最高不确定性是采集框架在大量真实 URL 访问中的吞吐和风控表现。在框架选型前同时实现圈子发现、全部业务字段、数据库、前端和导出，会用可被选型结果推翻的工程工作阻塞关键风险验证。

## Decision

1. 当前采集框架 PoC 只使用甲方提供的真实帖子 URL 清单，不要求圈子列表发现、主评论、数据库、前端或导出。
2. 每个 URL 只在平台返回的帖子标识与输入对应，且至少取得标题或正文存在性证明之一时，才具备最小访问证明。
3. HTTP 200 不单独构成成功。验证码、挑战页、登录页、限流响应和异常空响应必须分类，不得冒充帖子内容。
4. 每轮使用 2000 个不同真实 URL，一小时内的最终完成率、帖子 ID 匹配率和内容证明完整率均为 100%，未恢复风控数为 0，该轮才通过。
5. `throughput-urls.txt` 是当前 PoC 必需输入；`functional-samples.csv` 仅作为后续第一版功能回归的可选基准，不是当前测试前置，也不是运行结果。
6. 当前 PoC 的逐 URL 结果保存在 `url-results.jsonl`，汇总保存在 `summary.json`，并保留请求事件、资源指标、日志和校验值。
7. 采集框架 PoC 通过后，第一版仍须实现并验收圈子发现、URL 清单提取、完整正文与主评论、数据持久化、定时调度、测试前端和 XLSX 导出。

## Consequences

- 候选方案能以最小原型先验证最高风险的规模访问与风控表现，减少选型失败时的返工。
- 通过 PoC 不能声称第一版功能已完成，也不能证明正文和主评论已达到最终完整率。
- 本决策仅替代 ADR 0004 中将“PoC 必需字段”等同于完整业务正文与主评论的部分；ADR 0004 的风控结果门禁、真实失败记录和绑定测试条件规则继续有效。
