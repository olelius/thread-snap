# 易车使用账号登录门禁和直连 HTTP 采集

历史 `yiche-community-v1` 通过页面浏览器产生动态签名并监听真实 XHR，只证明访问环境可用，没有证明易车账号身份。2026-08-30 对当前公开 PC 脚本、页面 XHR 和直接请求进行同参数验证后，已确认列表与评论的 `pc-v311` 签名合同，并确认详情 HTTP 203 控制文档可以在不执行脚本的前提下严格解析一次 Cookie 挑战。真实瑞虎8样本在零 Chromium 进程下取得50条列表、详情正文/媒体及评论业务成功，因此后台浏览器不再是必要依赖。

易车改用与懂车帝、汽车之家一致的 `account_login` 状态机：人工操作服务器浏览器打开官方登录页，导出并加密 Session；完成门禁必须同时存在非空 `username` 账号 Cookie，并由官方用户消息接口返回非空 `userId`。只有安装标识、城市信息或203挑战Cookie的历史访问会话不构成登录证明。

## Consequences

- 易车适配器升级为 `yiche-community-v2`；列表、详情、评论、来源验证和 URL 清单提取全部使用直连 HTTP，不在响应不完整、协议变化、验证码或限流后启动浏览器补量。
- PC 请求签名按冻结协议逐请求生成；详情203挑战只解析固定有限变量和已确认的重载边界，最多重试同一URL一次，未知结构以稳定错误失败关闭。
- 浏览器只保留给共享认证状态机的人工账号登录与有界Session刷新；易车仍不支持圈子页面证据。懂车帝的后台列表浏览器回退同时移除，汽车之家已确认本来就是直连HTTP。
- Session失效继续复用 ADR 0007 的 `waiting_for_auth`、有界刷新、原批次检查点续跑和平台FIFO，不新增账号密码字段，也不向接口或日志输出Cookie值。
- 正式易车500条必须在新账号Session和 `yiche-community-v2` 条件下从冻结输入完整重跑，历史访问会话结果不与新轮次拼接。
