# ADR 0027：采用有界干净纠正与单候选结构恢复

- 状态：已接受
- 日期：2026-08-24

## 背景

DeepSeek 文字舆情在启用 `response_format=json_object` 且流正常结束时，仍多次把根级 `summary` 放入 `modalities`，同时少返回一个右花括号。2026-08-24 的 150 条真实批次中有 5 条首次出现该语法错误；原有纠正修复 3 条，另 2 条的纠正响应与首次响应 SHA-256 完全相同。原逻辑把错误候选作为 assistant 历史再次提交，在低温度下形成了稳定复现锚点，也没有满足使用者对最终分析失败为 0 的正常验收目标。

## 决定

1. 云端候选首次违约后仍只进行一次付费格式纠正；纠正请求保留最初输入，追加错误候选哈希、具体错误和原合同，不携带错误候选正文或错误 assistant 历史。
2. 模型调用最多两次，不因结果持续错误而永久重新排队。
3. DeepSeek 第二次响应只有在以下条件全部成立时才允许结构恢复：原始文本只有一个 `summary` 键候选；只需在该键前补一个 `}`；补字符后立即成为根字段精确匹配的 JSON 对象；随后完整通过 Pydantic、字段关系和输入身份校验。
4. 结构恢复不修改字段值、观点、枚举、数组、索引或哈希；两次原始失败响应、错误、请求审计和 `locally_recovered` 标记全部保留。
5. 候选不唯一、补一个字符后仍不合法或完整合同不通过时，任务以现有稳定错误码结束，不继续循环。

## 结果

- 已实证的稳定单括号错误可以在不产生第三次模型调用、也不改变模型语义字段的前提下形成完整结果。
- 重试次数和本地候选数都有硬上限，持续错误不会造成无限循环或无限 API 用量。
- 外部模型仍可能产生其他不可恢复错误；这些错误继续显式留存，后续只能基于新的真实失败分布增加经单独接受的窄规则，不能扩展成通用猜测式 JSON 修复器。

本决定细化 ADR 0025 的 DeepSeek 输出处理边界，不改变其纯文字输入、独立凭证或两个消费者架构。
