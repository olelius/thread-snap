# ADR 0031：在完整原始页面证据上生成负面框选成果

- 状态：已接受
- 日期：2026-08-24

## 背景

ADR 0026 要求同步冻结不可变页面证据，并在当前关联结果上生成版本化负面框选成果。最初实现把实际入库帖子从原图裁出后重新拼接成长图。该方式能集中展示结果，却丢失帖子在原始页面中的完整上下文、页面布局和未入库内容，也使“成果截图”和“原始截图”在尺寸与视觉结构上明显不同。

使用者确认仍沿用现有去重、舆情结论、卡片边界恢复和红框样式，只把成果底图替换为对应完整原始页面。

## 决定

1. 当前关联结果继续按既有跨补提规则去重和排序；渲染器按结果首次引用页面证据的顺序选择原始物理分页，不改变框选对象。
2. 每张被引用的原始 PNG 生成一张同宽高的完整副本。成果不裁切、不缩放、不重排卡片，也不插入标题栏、逐卡溯源条或其他页面外像素。
3. `negative` 继续使用既有卡片边界恢复和 5 px 红框；`non_negative` 与 `unrelated` 不绘制。除红框覆盖区域外，成果页的 RGB 像素必须与来源原图一致。
4. 渲染前校验原图 SHA-256；生成成果不得修改原图。清单记录每张成果页的来源证据 ID、来源批次、物理页码、捕获时间、原图哈希、成果哈希和卡片 `source_rect`。
5. 一张原始物理分页对应一个成果文件；多个页面共同属于同一个逻辑成果，由现有连续查看器和成果包按稳定顺序承载，不在成果阶段重新拼成长图或切割原页。
6. 渲染器版本和页面身份进入输入哈希。该规则上线及后续像素规则变化均创建新的不可变成果版本，历史版本继续保留。
7. 没有页面证据的历史“成功但零条”任务可保留既有零结果占位表现；存在真实原图的成果不得进入占位路径。

## 结果

- 使用者可以在完整页面上下文中核对负面框，且原图保持不可变。
- 同一原始页面只需校验、解码和编码一次；内存门禁从人工合成长图高度转为单张实际原页的最大尺寸。
- 成果文件数量由当前关联结果引用的物理分页决定，但业务仍只有一个当前逻辑成果和一套版本生命周期。
- Windows 与目标 Linux 需要重新验证同尺寸、框外像素一致、最大原页解码、连续查看、成果包和备份恢复；旧 v3 的 30,000 px 裁片上限只保留为历史事实。

本 ADR 只替代 ADR 0026 第 3 项中的“裁取卡片”合成方式和第 6 项中的“按卡片切分超长合成图”方式；同步页面证据、关联成果组、舆情优先级、版本化、状态、生命周期和页面入口等其余决定继续有效。
