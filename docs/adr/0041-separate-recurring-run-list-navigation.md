# 为循环计划批次提供独立列表导航

循环计划批次与手动、每周定时批次在信息架构上分开。侧边栏保留“提取列表”并只展示 `manual` 与 `scheduled` 批次，另增“循环计划列表”入口并只展示 `recurring` 批次；两个入口使用独立列表路由，批次详情也从对应列表进入各自路由，使侧边栏选中状态、页面标题和返回入口始终保持在当前业务列表。

独立入口不复制业务实现。两个列表复用同一个列表组件、字段、状态筛选、来源类型筛选、日期筛选、分页、刷新、认证和行操作；两个详情路由复用同一个详情组件、状态机、帖子结果、截图成果、重试、导出和删除能力。循环计划列表固定后端查询范围为 `recurring`，提取列表固定为 `manual` 与 `scheduled`，不再用同一页面中的“循环计划”触发方式选项承担业务分隔。

“新建提取”仍只属于提取列表，因为它创建手动批次；循环计划列表不提供伪造或手动创建循环批次的入口。后端批次列表 API 增加可重复的 `trigger_types` 精确集合过滤，同时保留既有单值 `trigger_type` 兼容调用；分页总数与结果必须在服务端完成类型过滤后计算。

本决策部分替代 ADR 0040 中“循环与定时批次在同一列表筛选中区分”的界面安排；ADR 0040 关于循环触发语义、独立 `recurring` 类型、调度和共享业务能力的其余决策继续有效。
