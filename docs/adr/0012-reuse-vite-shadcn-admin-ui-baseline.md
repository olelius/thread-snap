# 选择性复用 Vite shadcn-admin UI 基线

第一版需要在既有 FastAPI `/api/v1` 上形成现代、数据密集、桌面优先且带状态动态的内部运营控制台。相比自建全部 UI 原语或采用绑定 Next.js、Clerk、组织和计费能力的完整 SaaS 模板，项目选择 React、TypeScript、Vite、shadcn/ui、Tailwind CSS、TanStack Router/Query/Table、Lucide 和 Motion for React，并以 MIT 许可的 `satnaing/shadcn-admin` 作为应用外壳与 UI 原语的上游基线。

## Decision

- 实施开始时固定上游提交，记录仓库地址、提交 SHA、许可证和实际复用文件，并在第三方说明中保留来源。
- 选择性复用应用外壳、主题 Token、Sidebar、Header、导航状态、响应式 Sheet、表格、表单、弹层、反馈和可访问性基础；业务页面按 ThreadSnap 的三个页面和真实 `/api/v1` 重组。
- Sidebar 的展开/收缩、键盘触发、状态持久化、宽度和位置过渡、图标与文字层级及窄窗 Sheet 行为属于 UI 基线，不在业务裁剪中重写或降级。
- 示例登录、Clerk、示例用户、示例图表、假数据页面、RTL 专项和无关 SaaS 能力不进入第一版依赖面。
- 上游英文示例文案不进入交付界面；项目保留组件结构、状态和视觉特性，但业务可见文案统一使用中文，仅保留必要的品牌名、协议名和专业缩写。
- 第一版中文文案直接进入业务组件，公共状态和高频组件文案集中维护；通过专业术语允许清单、自动化 DOM 与无障碍文案扫描以及真实页面检查防止选择性复用留下英文，不增加单语言阶段的翻译运行时和语言切换状态。
- 保留上游深浅主题能力，默认跟随系统，并允许用户在浅色、深色和跟随系统之间切换；项目新增组件必须使用同一主题 Token，而不是建立第二套主题实现。
- 冷调科技配色只是当前视觉假设，不属于不可替换的 UI 基线；颜色必须通过语义 Token 和浅深主题变量集中映射，使后续 Figma 或真实页面评审可以整体换色而不修改业务组件。
- 第一版不制作 Figma 设计稿，直接以真实 React 页面验证视觉和动态；三个平台全部完成后再从实际前端反向建立 Figma 变量、组件映射和页面稿，设计结果必须受现有组件、接口与运行能力约束，并与代码保持可复核对应。
- 第一版不设置独立的主观视觉签收阶段，以功能闭环、功能完整性和组件一致性为主；同规格组件必须复用同一 Token 和命名变体，页面级一次性视觉分叉不进入实现。
- 页面优先使用已选上游和官方 shadcn/ui 的现有组件；有业务差异时先组合现有原语形成应用级组件，只有组件体系确有缺口时才新增底层实现，避免反馈、加载和弹层脱离整体视觉语言。
- 保留上游响应式 Sidebar Sheet 和组件行为；第一版按 1280px、1024px、768px 分层收敛信息，窄屏表格继续使用同一 DOM 与横向滚动，不另建一套手机卡片页面。
- CSS/Tailwind 承担高频轻量过渡，Motion for React 承担页面、弹层、批次状态、表格行、数字与进度等具有明确因果关系的动态；系统减少动态效果偏好使用弱化表现。

## Consequences

- 选择性复用会减少上游示例功能数量，但已定义的 UI 基线由原组件、设计 Token、组件测试和视觉证据共同保留，因此不会因删除示例业务而丢失导航、主题、表格、弹层和反馈的核心体验。
- 项目不跟随上游整仓持续合并；升级时只评估已复用组件，避免示例业务、认证和 SaaS 依赖重新进入第一版。
- 前端保持静态 SPA 和同源页面 API 边界，与现有 FastAPI 后端和后续停用第一版前端的集成路线一致。
