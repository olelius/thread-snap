# JSON迁移只在容器边界解码

**根因**：SQLAlchemy 的 JSON 列有时返回JSON文本、有时返回已解码容器；兼容函数只能在数据库列的最外层解码一次。递归遍历时再次对字符串叶子执行 `json.loads()`，会把 `"-1"`、`"4.00"` 等业务文本静默转换成数字，破坏API类型合同和原始显示精度。

**坑**：只检查键是否删除会漏掉叶子类型变化；正数差值通常带 `+`，不是合法JSON数字而会保留字符串，导致问题只在负数差值批次出现，容易误判为单批次脏数据。

**杠杆**：修改 JSON 数据迁移时同时验证结构、叶子类型和原始精度；至少覆盖 `"-1"`、`"+1"`、`"4.00"`、`null`，并用迁移前副本分别验证“跨过原迁移”和“已经受影响后执行修复迁移”两条路径。
