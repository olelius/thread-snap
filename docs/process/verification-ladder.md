# 验证阶梯

验证强度由变更风险决定。较高等级包含较低等级的全部要求。

## 🟢 低风险

适用：文案、纯文档、样式、只读展示。

- 执行适用的格式、静态、链接或构建检查；
- 对目标位置做直接检查；UI 变更必须看到真实渲染结果，不能只检查方法返回值；
- 执行 `git diff --check`；
- 核对实际暂存文件，没有夹带无关修改或敏感信息。

## 🟡 中风险

适用：业务逻辑、接口、调度、数据解析、导出、配置开关。

- 完成低风险全部要求；
- 以单元或集成测试覆盖修改路径和主要异常路径；
- 在隔离运行实例中真实触发目标路径，记录命令、输入身份、关键输出和退出状态；
- 有开关或兼容模式时验证开启和关闭两态；
- 涉及快照或导出时，核对批次隔离、字段完整性和数据库源数据一致性。

## 🔴 高风险

适用：凭证、权限、数据库迁移、公开部署、生产集成、PoC 技术选型硬门禁。

- 完成中风险全部要求；
- 验证无权限或无凭证路径确实被拒绝，日志与导出不泄露敏感信息；
- 验证重复执行、失败重试和补偿的幂等性；
- 数据迁移必须验证新旧数据兼容、回退或清理路径；
- 在等价环境或最终目标主机真实触发目标场景；
- PoC 结论必须绑定代码版本、测试包哈希、输入清单哈希、环境、时间、访问模式和完整原始结果；
- 回退方案在合并或发布前存在，并至少完成可执行性检查。

## 验收铁律

1. 构建、静态检查或单元测试通过，不代表目标业务场景已验收。
2. 子 Agent 或分支自报通过，只是证据输入；整合后必须由主线程或独立最终门真实触发组合路径。
3. “全部、没有遗漏、不存在”必须给出搜索范围、分母、排除项以及穷尽或抽样说明。
4. 没有命令、输入身份、关键输出或可复核产物的“已完成”，不得写成验证通过。
5. 高风险变更没有回退说明时，不进入自动 Git 收尾。
