# 项目进度文档规则

本目录保存阶段性状态和详细执行记录，避免 `AGENTS.md` 随开发过程持续膨胀。

## 文件职责

- `current-progress.md`：当前有效的项目状态摘要，是新任务恢复上下文的入口。
- 需要保留阶段历史时，新建 `YYYY-MM-DD-<阶段名称>.md`。

## current-progress.md 建议结构

1. 当前阶段；
2. 已完成；
3. 进行中；
4. 下一步；
5. 阻塞项与待确认事项；
6. 验证结果；
7. 相关分支或文档。

## 更新规则

- 每个有意义的功能阶段完成后更新；
- 分支合并前确认其内容与实际 Git 状态一致；
- 只记录必要的提交或分支信息，不复制完整日志；
- 测试结果写明执行命令和结论，避免只写“已测试”；
- 已失效的计划要标明替代项或移入历史文档；
- 不把敏感信息、Cookie、令牌或平台响应原文写入进度文档。
