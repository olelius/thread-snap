# 舆情反馈工作线

## 当前口径

- 功能范围 owner：`docs/design/product-design.md`。
- 技术路线 owner：`docs/design/technical-route.md`。
- 架构决策：`docs/adr/0022-use-hosted-multimodal-api-for-sentiment-feedback.md`、`docs/adr/0023-use-validated-runtime-config-for-sentiment-service.md`、`docs/adr/0024-add-local-text-sentiment-option.md`、`docs/adr/0025-add-deepseek-cloud-text-sentiment-option.md`。
- PoC 执行 owner：`docs/research/sentiment-analysis-poc-plan.md`。
- 当前阶段：使用者要求最终分析失败以 0 为正常验收目标。2026-08-24 现场批次 150 条中 5 条首次返回坏 JSON，原纠正链修复 3 条，另 2 条逐字复现同一单括号遗漏；当前改为不携带坏 assistant 候选的干净纠正，并仅对这一可唯一证明的结构错误构造一个候选后执行完整合同校验。模型调用最多两次、结构候选最多一个，仍保持失败审计和有界终止。
- 当前关键路径：模型配置提供千问云端多模态、DeepSeek 云端文字与本地轻量文字三个受控选项。千问 Worker 继续在含视频请求前按 `video_id` 直接 HTTP 刷新临时 URL；DeepSeek 和本地 Worker 只处理标题和正文，不进入媒体解析，其中 DeepSeek 使用独立加密云端连接，本地路径不进入外部 API。完整离线包必须携带已转换的 UIE-Senta-Nano 与 UTC-Nano，目标机不联网下载模型。

## 已确认边界

- 每帖只运行当前选择的一条分析路径，不是对话型智能体。千问路径固定使用 `qwen3.5-omni-plus-2026-03-15`，DeepSeek 路径固定使用 `deepseek-v4-flash` 并关闭 thinking；本地路径固定使用 UIE-Senta-Nano 与 UTC-Nano，不使用 RAG、工具、联网搜索或第二模型裁决。
- 千问输入为帖子完整标题、正文、全部图片 URL 和全部视频 URL；DeepSeek 与本地输入只有标题和正文，媒体覆盖统一为“未参与分析”；评论均不参与。
- 判定对象只配置目标品牌、重点产品和选填补充说明。云端模型结合语境判断别名和实际相关性；本地模型把配置名称作为 UIE 评价维度，对未抽取出观点的文本只识别明确名称，必须覆盖的别名需要作为重点产品配置。
- 视频必须分别处理画面和音频。ThreadSnap 优先直传 URL，不下载、中转、转码、抽帧或 ASR。
- 每次失败候选原始响应和最终严格通过的结构化结果同时保留；程序只校验合同与覆盖，不判定模型是否“答对”。单括号结构恢复不修改任何字段值，且必须重新通过完整合同；其他违约不在本地改写。
- 有效结果为负面、非负面或不相关；完整 AI 反馈可以成为默认有效结论，人工修正和继承人工结果优先且追加保存。人工复核随机发生，不设置强制比例或多人一致性流程。
- 关联圈子截图成果直接读取每个证据化帖子的当前有效结果，优先级仍为人工修正、继承人工结果、完整 AI 结果；不从截图 OCR，也不追加第二次模型判断。成果等待全部证据化帖子具有有效结果后生成，负面项框选整张卡片；人工结论变化或 AI 恢复会创建新的不可变成果版本，详见 `docs/chains/circle-screenshot-artifacts.md`。
- 同帖内容未实质变化时继承人工判定；无人工结果时只精确复用版本和输入完全一致的完整 AI 结果。任何历史批次保持不可变。
- PoC 是 URL 获取、模态覆盖、结构、耗时、用量、成本和失败分布报告，不设置准确率、召回率、误判率或漏判上限。
- 第一版以加密运行时配置、受控模型下拉和显式模型测试启用分析；千问与 DeepSeek 的 URL/Key 分槽加密保存，云端允许安全校验后的公网 HTTPS 兼容代理，本地不要求 URL/Key 且不开放自由本地端点；不增加余额查询。
- 列表分别筛选有效舆情结果与分析状态；人工入口只在详情的全局 Dialog 中提供，无有效结论时称“人工判定”，已有结论时称“人工修正”。运行、排队和暂停时禁止，完成、部分、失败和禁用时允许。
- 图片由浏览器按需直连快照 URL；打开含视频的详情 Sheet 时，前端自动触发后端使用快照 `video_id` 通过授权与播放信息 HTTP 接口刷新当前临时 URL，再由浏览器直连媒体 CDN并使用 `preload="auto"` 预缓冲。刷新过程不加载原帖页面或启动 Chromium，ThreadSnap 不为展示下载或代理；第一版不提供重新分析和历史回刷。
- 同一稳定媒体的多个查询、已知路径时效签名或等价懂车帝 CDN 主机 URL 只提交和展示一次；播放地址刷新返回最高码率地址，同一清晰度优先使用支持浏览器连续 Range 播放的备用 CDN，缺失时回退主地址，原始快照不改写。模型 Worker 对含视频任务也在请求前按快照 `video_id` 刷新当前临时 URL，避免把已过期快照 URL 送入模型。模型 JSON 的字段、层级、类型、枚举、索引和哈希必须原生符合合同；DeepSeek 严格通过后仅由后端追加其未接收媒体的 `not_requested` 事实。
- 舆情队列保留两个消费者；云端请求可以并发，缺少正常流结束标志或明确长度截断时保留首次失败审计并完整重请求一次。正常结束但严格合同违约时，保存候选与具体校验错误，使用原始输入、候选哈希、错误和原合同进行一次干净纠正；DeepSeek 纠正后仍为已实证的单括号遗漏时只构造一个本地候选并完整复验。模型格式调用最多两次、结构候选最多一个，不把失败任务永久重新排队；媒体部分结果不作为格式错误重发；429 使用共享冷却且最多重试一次，其他可重试传输错误保留有界退避。本地 Taskflow 的配置测试与 Worker 推理统一投递到一条专用线程串行执行，禁止跨线程复用 Paddle Predictor，且不触发云端格式纠错规则。

## 决策链

| 日期 | 决定 | 为什么 |
|---|---|---|
| 2026-08-19 | 不采用本地语义小模型或对话型 Agent，改用每帖一次的在线多模态 API | 需求是确定输入到结构化结果的单次处理，没有对话、规划、检索或工具使用；本地方案的视频画面与音频能力也未获证据 |
| 2026-08-19 | 第一轮固定百炼 `qwen3.5-omni-plus-2026-03-15` | 固定快照便于复现；官方接口允许文字、图片、音频和视频组合输入，真实 URL 能力仍须 PoC |
| 2026-08-19 | 优先让提供方直接读取完整媒体 URL | 避免 ThreadSnap 承担视频下载、磁盘、带宽和转码成本；防盗链与签名失败按真实样本分布再决策 |
| 2026-08-19 | 提取提交后创建同进程持久分析任务 | 隔离提取和外部模型延迟，同时复用现有单进程与 SQLite 部署，不提前引入消息中间件或微服务 |
| 2026-08-19 | 只保存和展示真实模型反馈，不建设准确率裁决门禁 | 当前目标是忠实保留单一模型返回，不存在要求每条复核的金标准流程；程序只验证结构和模态覆盖 |
| 2026-08-19 | 人工随机复核且结果优先，内容未变化时向未来快照继承 | 满足实际偶发纠正需求，避免重复修正同一内容，同时保持历史批次不可变 |
| 2026-08-19 | 当前无视频数据，先补至少 30 条真实视频样本 | 本地 842 个不同帖子中视频样本为 0，现有数据不能回答视频 URL、防盗链、画面和音频覆盖问题 |
| 2026-08-19 | PoC 限制为 30 条 URL 验证和 1 次千问调用，自动重试为 0 | 控制 API 调用消耗，同时用不同分母分别回答媒体传输和端到端模型链路问题 |
| 2026-08-19 | 保持 URL 直传并进入最小实现 | 30/30 播放 URL 可公开访问；一次模型调用实际计入视频和音频 Token，未出现必须下载媒体的证据 |
| 2026-08-20 | 模型服务改为加密、显式测试的运行时配置 | 部署后需要替换 Key、端点和启停分析，但不能把密钥返回前端或让未验证配置直接产生费用 |
| 2026-08-20 | 判定对象收缩为品牌、重点产品和选填说明，相关性由模型判断 | 人工维护服务、别名和事件词典成本高，短车型名的后端关键词命中也容易制造误判 |
| 2026-08-20 | 视频临时地址改用两段直接 HTTP 解析 | 网页实际先以 `video_id` 获取播放授权，再调用 VOD 播放信息接口；两接口省略网页动态签名后仍返回完整 JSON，因此详情加载和视频帖采集不再启动 Chromium |
| 2026-08-20 | 打开含视频详情时自动加载播放器 | 直接 HTTP 解析耗时和资源已显著降低；自动获取 URL 可减少一次无意义点击，同时保持不自动播放、失败重试和显式刷新 |
| 2026-08-20 | 有效结果扩为负面、非负面和不相关，并把人工修订收敛到详情 Dialog | 不相关不能伪装成非负面；详情具备正文、媒体和模型依据，适合在保持列表紧凑的同时完成随机复核 |
| 2026-08-20 | 关闭、暂停和禁用采用独立状态语义 | 已发出的请求继续可避免浪费费用；用户主动关闭的数据不应在重启后意外回刷，配置故障任务则需要恢复 |
| 2026-08-20 | 舆情闭环进入正式实现 | 复用现有 FastAPI、SQLite、SSE、React 与 Sheet，不增加消息中间件、第二后端或媒体下载链路；以独立持久 Worker 隔离模型延迟 |
| 2026-08-20 | 修复真实批次的结构、重复媒体和吞吐问题 | 只归一化可证明的 JSON 形状并保留原始响应；稳定媒体只提交一次；固定两个消费者提升吞吐且避免无效重复付费请求 |
| 2026-08-20 | 详情视频改为显式刷新临时播放 URL | 已保存 CDN 地址约一小时后返回 403，当前地址携带本地 Referer 也返回 403；按需解析加无正文、无 Referer 重定向保留浏览器 URL 直连与不可变快照边界，同时避免后端下载、存储和带宽占用 |
| 2026-08-20 | 模型调用前刷新视频 URL，并由后端归一化冗余结构元数据 | 真实续跑确认历史临时 URL 已过期；模型的观点字段稳定，但覆盖枚举、匹配项形状和复制型哈希存在波动。这些字段可由本次输入和计数唯一确定，后端修正规范化结果并保留原始响应，避免为同一真实回答重复付费 |
| 2026-08-20 | 最高码率内优先备用播放地址 | 3 条真实视频的主 CDN 均缺少 `Accept-Ranges` 并在浏览器首段缓冲末尾停滞；同画质备用 CDN 均声明字节范围能力，沿既有 307 URL 直连路径可完整播放，不增加后端媒体流量 |
| 2026-08-21 | 截断响应完整重请求一次 | 真实9图请求在哈希字符串中重复并提前结束，同输入再次请求以 `finish_reason=stop` 正常完成；只对可识别截断增加一次付费重试，并保留首次原始响应，避免把普通结构偏差或部分媒体结果无条件重发 |
| 2026-08-21 | 增加 PaddleNLP 本地轻量文字选项 | 仅需文字分析时无需承担媒体处理和逐帖 API 用量；受控 UIE-Senta/UTC 管线能复用现有结果合同，并明确接受其别名、语境和模板总结能力弱于云端模型 |
| 2026-08-21 | 增加 DeepSeek 云端文字选项 | 复用 OpenAI 兼容流式客户端和统一结果合同，但按提供方能力只发送判定对象、标题与正文；独立保存连接，切换模型不覆盖千问凭证 |
| 2026-08-21 | 收紧 DeepSeek 文字状态合同 | 首个 30 条真实批次中 28 条返回 `analyzed`、2 条返回 `completed`，均不属于统一枚举；提示词 v2 显式列出 `absent` / `processed` / `unprocessed` 并给出完整 JSON 示例，同时只对这两个已完成同义值做确定性归一化，原始响应继续保留 |
| 2026-08-23 | 云端模型输出改为严格合同并增加一次带错误反馈的纠正 | 新批次 29/30 成功，唯一失败响应连续两次生成相同错层 JSON；原样重发没有告诉模型错误，本地逐类适配又会模糊“合规才正确”的边界，因此停止修改模型负责字段，改为严格校验后携带具体错误纠正一次 |
| 2026-08-24 | 重复坏 JSON 改用干净纠正与单候选结构恢复 | 150 条真实批次中 5 条首次违约，2 条纠正响应与首次 SHA-256 完全相同；错误 assistant 历史会锚定坏结构。移除该历史后仍只调用一次纠正，对唯一可证明的 `modalities` 少一个结束括号只补一个字符并执行完整合同，避免无限循环和语义改写 |
| 2026-08-22 | 截图成果复用当前有效舆情结论并实行严格生成门槛 | 避免截图 OCR 或第二模型产生双重口径；所有证据化帖子都有有效结论后，单条和多条负面框选才具备完整分母 |
| 2026-08-21 | 暂缓处理批次详情空列表刷新与本地推理资源争用 | 数据库和接口均确认目标批次实际有 30 条；前端首次取得 0 条后不会跟随批次进度刷新，本地 Taskflow 推理期间帖子接口又偶发延迟 10.8～14.1 秒。使用者要求先登记，不在当前任务修改运行代码 |
| 2026-08-21 | 以数据版本刷新详情并限制本地推理 CPU 预算 | 使用者重新安排该项；`summary_version` 进入帖子查询缓存键，运行批次持续查询，Taskflow 固定 2 个 CPU 数学线程。2 线程本机组合基准中模型验证 5.25 秒，23 次并发列表查询 0 失败、P95 81.5 毫秒，锁竞争另由 SQLite 15 秒有界等待处理 |
