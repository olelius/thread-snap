## 已确认边界

- 所有实际执行的圈子发现任务固定生成页面证据，不增加截图开关；任务冻结什么来源链接就截什么来源，未执行来源和 URL 清单不进入。
- 页面捕获是列表身份、顺序和卡片范围的事实来源；详情采集只消费冻结清单。一个平台只运行一个受控页面捕获器，并在平台资源预算内与详情采集流水线重叠。
- 卡片矩形和原始 PNG 必须在相同的无滚动条页首稳定布局中取得；验收同时抽查首部、中部和末部卡片，防止宽度重排造成逐卡累积的纵向漂移。
- 物理分页原始证据不可变且要求实际入库卡片的文字、媒体和布局完整稳定；上下文结束后不对原批次补拍。
- 最终成果只拼接证据化帖子，卡片像素取自原始证据；直接复用当前有效舆情结论，负面整卡红框，不执行截图 OCR 或第二次舆情分析。
- 原批次及全部补提中的同一实际来源形成稳定成果组；当前结果跨批次合并，逐卡批次和捕获时间保留在成果清单与审计数据中，图片只含原始卡片像素和负面红框。补提、删除、人工修正和恢复 AI 产生新版本，当前版本唯一，历史版本可追溯。
- 全部证据化帖子具有有效结论后才生成最终成果；零负面生成无框成果，明确空列表生成零结果成果，错误零条和证据缺失不生成最终成果。
- 提取、舆情和成果状态分离；成果失败不改写提取状态，也不触发帖子失败项补提。原始证据完整时可本地重新生成，证据缺失只能通过新关联采集恢复。
- 正常成果为单 PNG，超长成果按完整卡片无损分片并由前端连续展示；一个成果组仍只有一个逻辑当前成果，不降低 2000 条采集上限。
- 功能上线前历史批次不补拍；截图证据和历史成果版本与贡献批次同寿命、进入备份、不自动过期，最后一个贡献批次删除后清理成果组。
- 页面入口固定为现有批次详情中的“页面截图”标签；提取列表只显示紧凑成果摘要，不新增顶级导航或第二份批次列表。

## 决策链

| 日期 | 决定 | 为什么 |
|---|---|---|
| 2026-08-22 | 页面证据与详情采集共用同一冻结清单 | 独立并行请求仍可能因列表瞬时重排产生不同帖子和顺序，时间接近不是可复核一致性 |
| 2026-08-22 | 原始分页证据与派生关联成果分开 | 跨页、补提和失败补位需要合成实际入库卡片，但不能把派生图冒充单时点原始页面 |
| 2026-08-22 | 严格等待全部有效舆情结论 | 未决帖子不能默认为非负面；人工判定可以按现有优先级补齐 |
| 2026-08-22 | 原批次和补提按同一实际来源合并 | 使用者需要当前完整成果，同时必须保留每次采集时点和不可变原始证据 |
| 2026-08-22 | 成果组独立于任一批次所有 | 删除原批次或任一补提后，其他贡献数据仍应保留并重建当前成果 |
| 2026-08-22 | 当前成果版本化并保留历史 | 补提、删除和人工修正都会改变红框或分母，覆盖旧文件会丢失审计链 |
| 2026-08-22 | 超长成果允许底层分片 | 当前每圈允许 2000 条，始终生成单个超高 PNG 会造成编码、解码和内存风险 |
| 2026-08-22 | 不增加截图开关或历史补拍 | 截图是圈子任务固定证据，开关会扩大配置面；事后页面不代表历史采集时刻 |
| 2026-08-22 | Windows 候选分片上限采用 30,000 px 以下且只在卡片间切片 | 2000 卡片等价负载以 25 片完成，最大 29,988 px、0 切卡、0 遗漏，渲染峰值约 242 MiB；该值仍待目标 Linux 复核 |
| 2026-08-23 | 业务实现采用串行页面捕获通道和有界并发详情池 | 同一平台只冻结一个页面 DOM，同时允许该捕获与其他任务详情请求重叠；同页详情按平台并发批量执行并保持清单顺序提交 |
| 2026-08-23 | 页面证据、成果版本、分片与卡片审计项分别持久化 | 原始文件保持不可变，当前成果可重建，历史版本、逐片哈希、卡片来源批次和捕获时间均可独立追溯 |
| 2026-08-23 | 逐卡溯源信息退出成果图片 | 贡献批次与捕获时间属于审计元数据，不属于圈子页面像素；成果图只在原始卡片上叠加负面红框，汇总溯源改由查看器摘要和成果清单承载 |
| 2026-08-23 | 捕获前固定无滚动条页首布局，旧证据由原图像素恢复卡片边界 | 全页截图会改变滚动条占位并触发图片网格重排；预防新证据漂移的同时，历史原图保持不可变并以新成果版本校正展示 |
