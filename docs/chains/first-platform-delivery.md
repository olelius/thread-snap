# 链档：首个平台交付

## 当前口径

- 第一版是内部验证版，采用自建 Web 前端和一个独立提取后端完成一个平台的基础闭环；后端同时提供页面 API 和稳定集成 API，两者共用同一业务层。圈子列表发现与已知帖子 URL 清单复用同一详情采集流程；后续平台通过统一采集器契约接入。
- 第一版只有懂车帝适配器可以运行；前端可以展示和保存其他平台配置，但后端接入状态保持 `not_integrated`，禁止启用、手动提取或创建空任务。懂车帝动态版块支持 `https://www.dongchedi.com/community/24729` 的最新回复顺序和 `/dongtai-release` 的最新发布顺序；两者是同一平台圈子的独立来源配置和任务，正式验收分别验证入口与顺序。
- 配置采用“每周计划节点引用版本化规则 + 平台共享运行参数 + 多个圈子列表来源”的分层结构。规则按平台明确多选来源，两类列表来源复用相同规则结构和数量口径，但按实际提交分别形成批次；平台全选保存为当时明确来源 ID，新平台和新来源不自动加入旧规则。每个计划触发点最多创建一个顶层批次，执行时按平台维护严格 FIFO；认证只阻塞对应平台。第一版平台级并发固定为 1，平台内部总并发由前端配置并服从后端安全范围。
- 手动提取一次选择一个平台、多个圈子和一个统一每圈数量；已配置来源按“最新回复、最新发布”分组多选，每个分类支持三态全选并默认收起。自动规则采用相同列表顺序分组，切换规则或首次显示时分类同样默认收起。新圈子验证后进入独立手动历史但不自动加入定时。自动重试仍属于原批次，终态手动补提创建关联批次；关联展示不物理合并或改写原快照。
- XLSX 导出支持多个不可变版本模板，只使用 `s.<source_key>.<field>` 稳定英文标签定位数据；`source_key` 是跨平台全局唯一的 10 位持久化来源键，所有平台共用同一字段后缀注册表。第一版正式数据交付前清理，不保留 22 位来源键、UUID 长标签、圈子标签或 `vehicle.name` 兼容分支。一个帖子一行，评论、图片和视频集合在单元格内按顺序编号并换行；所有导出字段统一启用单元格换行，实际写入的列按表头与内容估算列宽并设上限，实际写入的数据行由表格软件按内容自动调整行高。
- 根据 ADR 0011，Python 第一版后端已先行实现；最终三轮吞吐门禁仍须在目标 Linux 主机由项目负责人手动触发，但暂不阻塞本次后端开发。
- 根据 ADR 0017、ADR 0018，第一版正式部署采用完整离线 `tar.gz`：目标包内置 Python wheelhouse、Patchright Chromium 和带本地仓库元数据的 CentOS RPM；systemd 管理单进程后端、Weston 无头 Wayland 与专用 Nginx，发布 SPA/API/SSE/WebSocket 并屏蔽 `/internal/v1`。最终服务器已从干净提交 `801c79c` 重建并切换到 `/opt/threadsnap/releases/0.1.0-801c79c95669`；本次依赖清单未变化，复用服务器内已校验的离线依赖，只替换后端、前端和部署内容，安装及二次快速验证均通过。
