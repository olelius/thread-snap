# ThreadSnap 功能设计

## 1. 文档状态

- 状态：初版功能基线
- 目的：规定产品功能、业务边界、分阶段交付和验收口径
- 不包含：具体编程语言、前后端框架、数据库、调度组件和部署方案

具体技术路线将在 `technical-route.md` 中单独评审和确认。

## 2. 产品定位

ThreadSnap 用于按需或按固定周期提取论坛、车友圈等社区版块中的帖子链接，并按执行批次保存结果。

每次提取都是一份独立快照。系统不持续跟踪单个帖子的后续变化，不覆盖旧批次，也不把不同批次自动合并为一条长期记录。

## 3. 交付阶段

### 3.1 第一版

第一版只交付一个经可行性验证的平台，形成完整业务闭环：

- 配置目标圈子与版块；
- 手动发起提取；
- 按固定周期自动提取；
- 查看提取批次及状态；
- 查看、搜索、复制和导出链接结果；
- 记录基础错误信息；
- 为后续平台预留统一采集器接口。

首个平台名称暂不在本设计中锁定，应以真实接口、访问条件和样本验证结果为准。

### 3.2 后续版本

在不重复建设公共功能的前提下，再接入两个平台。后续平台原则上只新增平台采集器、字段映射、配置选项及相应测试。

如果后续平台必须依赖验证码处理、复杂动态签名、代理池或浏览器自动化，应重新评估范围和成本，不能默认视为普通适配。

## 4. 用户与访问边界

- 第一版面向单一内部使用者或受控网络环境。
- 第一版不建设应用内登录、用户、角色和权限管理。
- 系统不得在没有外围访问保护的情况下直接暴露到公网。

## 5. 核心业务对象

### 5.1 监控配置

一条配置对应一个平台、一个圈子和一个版块。

建议字段：

| 字段 | 说明 |
|---|---|
| 配置名称 | 便于识别的名称 |
| 平台 | 第一版只有一个可选平台 |
| 圈子 URL | 用户提供的目标地址 |
| 圈子标识 | 从 URL 解析或验证后保存 |
| 版块 | 最新发布或最新回复 |
| 单次提取上限 | 默认 200 条 |
| 定时规则 | 第一版提供固定预设 |
| 启用状态 | 是否启用定时提取 |

第一版定时规则只提供简单预设，例如每小时、每天和停用；不提供用户自行填写 Cron 表达式。

### 5.2 提取批次

每次手动或定时执行均创建一个独立批次。

建议字段：

| 字段 | 说明 |
|---|---|
| 批次 ID | 唯一标识 |
| 配置 ID | 来源配置 |
| 触发方式 | 手动或定时 |
| 开始时间 | 实际开始时间 |
| 结束时间 | 实际结束时间 |
| 状态 | running / success / failed |
| 提取数量 | 本批次实际保存数量 |
| 错误信息 | 失败时的简要原因 |

### 5.3 提取链接

建议字段：

| 字段 | 说明 |
|---|---|
| 批次 ID | 所属提取批次 |
| 帖子 URL | 必需 |
| 标题 | 平台提供时保存 |
| 作者 | 平台提供时保存 |
| 发布时间 | 平台提供时保存 |
| 回复数 | 提取时的平台数值 |
| 点赞数 | 提取时的平台数值 |
| 版块 | 来源版块 |
| 平台帖子 ID | 平台提供时保存 |
| 可见状态 | visible / hidden / unknown |
| 原始状态 | 平台返回的原始值 |

平台未返回的非必需字段允许为空。不得为了填满表格而推断或伪造数据。

## 6. 功能模块

### 6.1 配置管理

- 查看配置列表；
- 新增、编辑、删除配置；
- 启用或停用定时规则；
- 测试配置是否能获取至少一条数据；
- 对指定配置执行“立即提取”。

### 6.2 手动提取

1. 用户选择配置并点击立即提取；
2. 系统创建运行中批次；
3. 调用对应平台采集器；
4. 分页获取并标准化数据；
5. 达到数量上限、没有下一页或列表为空时结束；
6. 保存链接并更新批次状态。

### 6.3 定时提取

- 启用的配置按预设规则自动触发；
- 与手动提取复用同一采集流程；
- 同一配置已经运行时，不重复并发执行；
- 失败时记录原因；
- 第一版不包含邮件、短信或企业微信通知。

### 6.4 批次管理

- 按时间倒序展示批次；
- 展示配置、触发方式、执行时间、数量和状态；
- 支持查看批次详情；
- 失败批次允许人工重新执行；
- 第一版不提供复杂统计图表。

### 6.5 链接结果

- 表格展示基础字段；
- 标题可点击跳转到原始帖子；
- 支持标题关键词搜索；
- 支持单条复制和批量复制链接；
- 支持导出当前批次为 CSV；
- 支持按可见状态筛选时，以平台状态验证结果为前提。

## 7. 平台采集器功能契约

所有平台采集器都应具备相同的业务能力：

1. 验证配置和访问条件；
2. 根据圈子、版块和分页参数获取一页数据；
3. 判断是否存在下一页；
4. 将平台字段转换为统一字段；
5. 返回可诊断的错误类型；
6. 保留必要的原始状态；
7. 遵守统一的数量上限、超时、重试和停止规则。

公共业务只依赖统一结果，不直接读取平台私有字段。具体接口形式和代码契约留待技术路线文档确定。

## 8. 可见状态规则

- `visible`：已有样本和字段规则证明帖子正常展示；
- `hidden`：已有样本和字段规则证明帖子被隐藏、删除、审核或不可正常展示；
- `unknown`：字段缺失、新状态值或证据不足。

需求中出现的 `status`、`visible`、`audit_status`、`fold_type` 等名称只是候选线索，不是已确认字段。

第一版不默认逐条请求详情页二次判断，否则会显著增加请求量。是否增加二次验证应单独评估。

## 9. 页面范围

第一版只包含三个基础页面：

1. 配置管理页；
2. 提取批次列表页；
3. 批次链接详情页。

页面以信息清晰和操作可用为目标，不包含品牌级视觉设计、移动端专项适配和复杂动效。

## 10. 第一版验收条件

第一版至少满足：

1. 一个指定平台已经完成真实样本可行性验证；
2. 可以创建有效配置并测试连接；
3. 可以手动提取并生成独立批次；
4. 可以按至少一种固定周期自动生成批次；
5. 达到上限或没有更多数据时能正常停止；
6. 成功批次可以查看、搜索、复制并导出链接；
7. 失败批次展示可理解的错误信息；
8. 不同批次互不覆盖；
9. 平台缺失字段和未知状态不会被伪造；
10. 已预留后续两个平台的接入边界。

## 11. 第一版不包含

- 应用内登录和权限系统；
- 第二、第三个平台的实际采集器；
- 自定义 Cron；
- 代理池、验证码识别和反风控规避；
- 默认使用浏览器自动化；
- 数据趋势、敏感词和高频账号分析；
- 邮件、短信和企业微信通知；
- 长期追踪帖子变化；
- 历史数据回刷；
- 平台改版后的长期免费维护。

## 12. 商务范围参考

当前首个平台基础交付范围由以下工作构成：

- 数据库、配置和批次管理；
- 手动及固定周期任务；
- 三个基础前端页面；
- 第一个平台采集器；
- CSV 导出和错误记录；
- 联调、测试和部署说明。

报价、付款节点和维护期限属于商务约定，不作为功能或技术事实写入本设计。
