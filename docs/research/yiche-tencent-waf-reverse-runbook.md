# 易车腾讯 WAF 逆向调研严格流程

## 1. 文档状态与职责

- 状态：已确认的调研流程；
- owner：本文件负责易车详情路由腾讯 WAF/滑块的证据冻结、工具链固定、动态分析、对照验证、阶段门和退出条件；
- 适用对象：已经被 ThreadSnap 分类为 `PLATFORM_CHALLENGE` 或 `PLATFORM_CAPTCHA_REQUIRED` 的易车原始详情 URL；
- 生产边界：本文件是隔离调研流程，不修改当前采集器、Session、数据库、前端、批次恢复或正式 `500 / 500` 验收合同；调研结论进入生产前必须另行修改产品设计、技术路线和相关 ADR，并通过目标场景验收；
- 原始产物：只进入 Git 外 `artifacts/poc/results/yiche-waf-reverse/<round-id>/`，仓库只保存脱敏结论、产物哈希和接受的决策。

## 2. 先恢复既有事实

### 2.1 已确认事实

1. 固定1000个不同详情 URL、实际并发1的批次已经完成 `1000 / 1000`、失败0；过程中在完成数59、118、840、897、954观察到5次腾讯验证码，并出现7次详情页HTTP 429冷却边界。
2. 验证码期间账号身份和列表 API 仍可用；同出口、同保存 Session 的新 HTTP 传输仍可得到 WAF 验证码，因此它不是单一旧连接状态，也没有证据支持“账号整体退出”。
3. 第3、4、5次验证码在约13分钟静默后，以同出口 IP、同账号、同 Profile、同触发 URL 且零滑块交互恢复正文；57～59条和约13分钟只是该轮观测，不是平台固定阈值或精确 TTL。
4. 当前生产分类、止损、持久冷却和原任务恢复由 ADR 0058 管理；已完成 URL 不重复请求。
5. 视频中出现的 MCP 已高置信识别为 [`zhizhuodemao/js-reverse-mcp`](https://github.com/zhizhuodemao/js-reverse-mcp)。与视频工具集合和时间线精确匹配的历史快照是提交 [`fb74ebf122cb26b229ebaf8ed5921b1acec0cdb5`](https://github.com/zhizhuodemao/js-reverse-mcp/tree/fb74ebf122cb26b229ebaf8ed5921b1acec0cdb5)，包版本为 `1.2.1`。
6. 历史 `1.2.1` 包含视频可见的 `inject_before_load`、`break_on_xhr`、`select_frame`、`evaluate_script`、`list_console_messages` 和 `list_network_requests` 等工具；上游提交 [`a3dbdf32f018210c273c317181026860df26f51f`](https://github.com/zhizhuodemao/js-reverse-mcp/commit/a3dbdf32f018210c273c317181026860df26f51f) 于2026-05-07移除了 `trace_function` 和 `inject_before_load`，所以“安装最新版”不等价于复现视频流程。
7. 视频对应的 MCP 工具层已经识别；视频中的私有 Skills/Rules 包没有公开、可独立核验的仓库证据。MCP、Skills/Rules 与本地项目代码是三个不同层次。
8. 视频在约99～108秒明确把“云码”列为滑块图片识别方案，并同时提到本地识别或 OpenCV；约458～490秒再次说明给 Agent 提供云码文档和 Token，验证码类型选择“双图滑块”。视频转写文件 SHA-256 为 `D022124267F3B46EF6FA1725FBFDDFDD866BADDA662EA10CCEF6EF771D774A56`。
9. [云码官方文档](https://www.jfbym.com/demo.html)的滑块缺口接口接收独立滑块图和背景图，通用双图滑块类型为 `20111`，识别结果中的 `data` 表示像素距离。它解决的是图像中的缺口定位，不负责腾讯 SDK 初始化、挑战图片取得、缩放换算、轨迹、加密参数、服务端校验或易车正文恢复。

### 2.2 合理推测

- 当前验证码更符合易车详情路由中按访问速率累积、随时间衰减，并叠加出口 IP、浏览器/Profile、设备状态和 WAF 清除状态的复合风险桶。
- 腾讯滑块页面可能复用腾讯验证码 SDK/TDC 体系，但“同属腾讯验证码”不证明易车与视频目标使用相同 AppId、配置、参数生成路径、风险策略或服务端验签合同。

### 2.3 尚待验证

- 易车挑战当轮的 `CaptchaAppId`、SDK/TDC 和业务脚本精确版本及哈希；
- 滑块令牌与原详情请求放行之间的完整请求链、Cookie 名称变化和有效期；
- 出口 IP、账号、Profile、设备状态、访问速率各自的独立权重；
- 历史 `1.2.1` 在当前 Node、Chrome/CDP 和 Codex MCP 客户端中的兼容性；
- 视频流程是否最终完成了目标站闭环。视频画面本身不构成易车成功验证证据。

历史源码和依赖审计通过后，待执行的 Codex MCP 配置命令固定为：

```powershell

```

### 3.1 云码在视频流程中的准确位置

视频展示的完整职责链应拆成：

```text
MCP/协议分析取得挑战和两张原图
  -> 图像预处理与尺寸记录
  -> 云码双图滑块识别，返回缺口像素距离
  -> 按原图、展示图和滑轨尺寸换算坐标
  -> 轨迹与腾讯协议参数生成
  -> 挑战验证请求
  -> WAF状态变化
  -> 易车原详情URL正文门禁
```

云码只占其中“识别缺口像素距离”一步。它与 MCP 的关系是上游/下游协作，而不是替代关系：MCP负责找到图片来源、调用点、缩放和协议链；云码负责识图；本地代码负责坐标换算、轨迹和已证明的协议计算；最终仍以原详情 URL 的正文合同判定结果。

采用云码时必须记录：服务名称与文档版本、识别类型、两张输入图的 SHA-256 和原始尺寸、返回距离、耗时、计费结果、缩放公式与最终换算值。Token只通过运行时密钥注入，报告和 Git 只记录是否配置及脱敏哈希。采用本地模型或 OpenCV时沿用相同输入输出合同，便于准确率、延迟、成本和数据边界对照。

## 5. 严格阶段流程

### 阶段0：复用既有证据，禁止重跑已完成压力轮次

1. 读取 `WORKLOG.md` 最新易车条目、ADR 0058、后续平台链档和固定1000条脱敏根因报告。
2. 校验根因报告 SHA-256：`3737de8252999f97d1c7a9a4b577181d8d4fa26df78100997ff334486a35d800`。
3. 把现有结论写入本轮 `manifest.json` 的 `prior_evidence`，明确哪些问题已经关闭、哪些仍开放。

**阶段门**：既有事实、推测和开放问题已分开；不得重新发起1000条轮次来重复证明单并发也会触发控制。

### 阶段1：冻结 MCP 与浏览器工具链

1. 先审计历史提交源码、`package.json`、MCP 工具清单、依赖和启动参数；记录源码提交与包版本的对应关系。
2. 默认复现实验固定 `js-reverse-mcp@1.2.1` 和提交 `fb74ebf122cb26b229ebaf8ed5921b1acec0cdb5`；如改用当前版本，必须另建兼容性矩阵，不得把新旧工具名视为等价。
3. 固定 Node、Chrome/Chromium 和 CDP 端口；浏览器使用单独用户数据目录，CDP 只监听回环地址。
4. MCP 只允许写入本轮 Git 外目录；启动前记录配置备份和删除 MCP 项的回滚命令。
5. 先用本地静态测试页验证页面选择、frame选择、脚本列表、网络列表、断点、暂停/恢复和截图；不得用易车挑战页作为工具安装自测。

**阶段门**：工具清单与版本可复核，静态测试页最小能力通过，输出目录受控，配置可回滚；任何一项不满足则不连接真实挑战页。

### 阶段2：等待自然挑战并冻结最小证据

1. 沿用当前生产止损：真实任务首次出现 `PLATFORM_CHALLENGE` 或 `PLATFORM_CAPTCHA_REQUIRED` 后停止新增详情请求，保留检查点。
2. 使用现有 Profile 打开该任务记录的原触发 URL；保留 Cookie、账号和出口原状，不主动制造高频访问。
3. 先只采集：最终 URL 类型、HTTP 状态序列、iframe 树、可见挑战类型、脚本 URL、脚本 SHA-256、请求时间线、挑战前后 Cookie **名称集合**变化和原 URL 正文门禁结果。
4. 若页面自然恢复，仍记录恢复时间和正文门禁，不补做滑块来追求样本。

**阶段门**：必须确认当前对象是易车详情路由中的腾讯 WAF/验证码页面，而不是账号登录页、普通403、HTTP 429或业务正文；此前1000条轮次只确认过控制分类和复合风险桶，尚未冻结上述 SDK/iframe/脚本级证据。

### 阶段3：建立状态机和请求归因

按实际证据建立而非预设以下链路：

```text
原详情请求
  -> 挑战响应/重定向
  -> 验证页主文档
  -> 腾讯 iframe 与 SDK/TDC 脚本
  -> 挑战交互及结果请求
  -> WAF 状态变化
  -> 原详情 URL 复访
  -> 正文内容门禁
```

对每个箭头记录触发事件、请求方法、目标域类别、调用发起者、关键字段名称、状态码、Cookie 名称变化和前后条件。账号身份接口、列表 API、详情页、评论 API 和验证码服务分别建泳道，不以时间接近代替因果关系。

**阶段门**：每个已声明的因果边都有网络发起者、调用栈或受控对照支持；只有相关性时标为“推测”。

### 阶段4：动态 JavaScript 分析

1. 先 `list_scripts`、`get_script_source` 并按 SHA-256 去重，再检索 AppId、TDC、验证码构造、XHR/fetch、postMessage、Cookie 写入和结果回调相关符号。
2. 先用 `get_request_initiator` 和 `break_on_xhr` 缩小范围，再在明确文本或调用点设置最少断点；一次只回答一个问题。
3. 在暂停点记录脚本哈希、frame、调用栈、参数**类型/长度/脱敏哈希**、返回值形状和网络请求关联，不记录敏感原值。
4. 只有断点尚未覆盖初始化前路径时，才评审历史 `inject_before_load`；启用前保存原页面、列出注入内容、限制到当前调研 Profile，并在轮次结束后关闭。
5. `evaluate_script` 仅用于读取已经存在的状态或验证局部假设；禁止把未知脚本整段注入生产 Profile，也不把控制台输出当作服务端验签成功。

**阶段门**：形成可复核的“脚本哈希 -> 函数/调用点 -> 输入形状 -> 输出形状 -> 网络请求”映射；尚未闭合的字段明确标记未知。

### 阶段5：滑块图片识别与坐标换算

1. 从已经冻结的网络证据中取得背景图与滑块图原始响应，记录内容哈希、像素尺寸、alpha通道、裁剪、拼图还原和展示CSS尺寸；不以整页截图代替可取得的原图。
2. 云码路径按官方“双图滑块”合同提交两张挑战图片并取得像素距离；Token只从运行时密钥读取。第三方请求只发送本轮挑战图片和必需类型，不携带账号、Cookie、Session、原详情URL或页面其他内容。
3. 本地对照可使用本地模型或 OpenCV，同样输出原图坐标系中的缺口位置、置信信息、耗时和失败分类；同一图片至少保存一次云端/本地对照结果后再选择路线。
4. 明确区分三个坐标：识别服务返回的原图缺口位置、页面展示图中的位置、滑轨实际拖动距离。换算必须由原图尺寸、CSS展示尺寸、滑块初始偏移和滑轨边界共同确定，并以页面观测复核。
5. 云码识别成功只关闭“缺口位置”问题；轨迹、指纹、加密参数、一次性挑战状态和服务端验签仍由后续阶段独立验证。

**阶段门**：两张输入图可追溯、坐标系和缩放公式明确、Token零落盘、返回距离可由独立方法复核；坐标识别不得记为腾讯验证成功。

### 阶段6：最小复现与环境边界

1. 从已冻结脚本和调用栈提取最小依赖图，分别标记纯计算、DOM依赖、浏览器 API 依赖、Profile/设备状态依赖和服务端一次性状态。
2. 先在隔离浏览器中重放只读计算，再在本地静态 fixture 上验证输入输出形状；不向平台批量发送重放请求。
3. 明确区分：
   - **算法已理解**：输入、变换和输出可由本地 fixture 重复验证；
   - **浏览器上下文必需**：结果依赖 Web API、iframe、TDC、指纹或运行时状态；
   - **服务端一次性状态必需**：离线计算不足以证明服务器会接受；
   - **仅观察到相关性**：尚无因果证据。
4. 所有派生脚本注明来源哈希、最小修改、用途和失效条件。

**阶段门**：本地复现结果与真实网络成功分开表述；不得以“生成了同形字段”推定已经通过服务端验证。

### 阶段7：单变量对照验证

只在新的自然挑战窗口、生产任务已止损且有明确证据缺口时执行。每轮只改变一个变量，并限制为最小请求数：

| 对照 | 固定项 | 改变项 | 可回答的问题 |
|---|---|---|---|
| A | URL、时点、账号、Profile、出口 | HTTP 传输实例 | 是否局限单连接/传输会话 |
| B | URL、时点、账号、出口 | Profile | 是否存在浏览器/Profile权重 |
| C | URL、时点、Profile、出口 | 账号 | 是否存在账号权重 |
| D | URL、时点、账号、Profile | 独立出口 | 是否存在出口 IP 权重 |
| E | URL、账号、Profile、出口 | 静默时间 | 风险状态是否随时间衰减 |
| F | URL、账号、Profile、出口 | 明确节流参数 | 访问速率和请求间隔影响 |

对照 B～D 涉及额外 Profile、账号或出口，只在相应资源已经单独准备且不污染当前任务时执行。每轮记录开始风险状态、请求数量、时间、控制分类、正文门禁和恢复情况；一旦观察到控制立即结束该轮。

**阶段门**：结论只覆盖实际改变的变量和该轮环境；单轮、单出口结果不外推为普遍规则。

### 阶段8：结果决策

调研只允许收敛到以下一种可审计结论：

1. **证据完成，生产保持现状**：继续分类、止损、静默恢复或人工交互；
2. **有界人工交互可集成**：只优化挑战窗口、Profile继承、返回原 URL 和正文门禁；
3. **协议链已理解但只保留研究产物**：维护成本、版本漂移或服务端一次性状态使其不进入生产；
4. **提出新的生产方案**：另开需求和 ADR，明确版本锁定、失效检测、回滚、测试与正式500条影响，再进行代码实现。

**完成门**：`report.md` 必须逐项列出已确认事实、合理推测、未验证项、证据入口、失效条件和建议决策；没有原 URL 正文门禁的“页面200”不记为成功。
