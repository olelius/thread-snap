# 后续平台接入验证计划

## 1. 文档状态

- 状态：已确认计划；汽车之家和易车均已完成本地适配器及共享业务闭环，均注册为 `available` 且默认停用；两个平台的正式500条均尚未执行；
- 适用平台：汽车之家、易车；
- 目的：用项目从真实社区页面生成的冻结样本，验证两个新增平台适配器的来源发现、帖子详情、主评论、媒体、状态、认证和平台控制合同；
- 决策依据：ADR 0043、ADR 0044、ADR 0045；
- 非目标：重新比较Python/Node候选、重做懂车帝2000条技术选型、宣称目标CentOS连续三轮门禁通过、提前启用未完成五指标验证的口碑平台。

## 2. 输入责任

| 内容 | 责任与处理 |
|---|---|
| 社区页面 | 使用外部配置说明中的真实社区页面作为发现种子；业务说明把车型与三平台URL指向关联表“说明汇总”区域，匿名访问受限时保留受限事实；完整URL只保存在Git外输入目录 |
| 最新回复/最新发布入口 | 项目通过实际点击、页面导航或可证明的页面链接关系取得并分别验证 |
| 易车缺失来源 | 按真实缺失保存，不补占位、不猜测替代、不阻塞其他存在来源 |
| 500条帖子URL | 项目从对应平台社区页面发现、规范化、去重、现时复核并冻结；每个平台各500条 |
| 功能样本 | 项目从发现池分层生成并记录覆盖与缺口，不要求外部填写样本表 |
| 访问条件 | 汽车之家与易车都固定使用正式官方账号登录与加密Session；采集阶段只使用直连HTTP，易车额外以账号Cookie和官方用户身份接口证明登录 |
| 27款口碑映射 | 项目生成汽车之家和易车候选及证据，仍走现有验证与发布门禁 |
| 口碑评价篇数、差评率来源 | 本阶段延期，不进入帖子适配器验收，也不启用两平台正式口碑巡检 |

### 固定500本地执行入口

统一入口为 `poc/shared/later_platform_acceptance.py`。`community-seeds.json` 顶层使用 `community_seeds` 数组，每项只需稳定的 `seed_identity` 与真实HTTPS `community_url`；汽车之家Provider会为每个seed分别验证最新回复和最新发布。正式执行顺序固定为：

```text
sources -> discover -> freeze -> samples -> verify-inputs -> run -> verify-run
```

各阶段使用 `python poc/shared/later_platform_acceptance.py <子命令> --help` 查看路径参数。`freeze`、`run` 与两个验证子命令的分母由代码常量固定为500，CLI不暴露数量参数；输出必须写入Git外既定输入或结果目录，已有冻结文件或轮次目录不会被覆盖。

## 4. 执行阶段

### 阶段0：来源盘点

1. 对每个已存在社区页面记录平台、业务车型身份、页面可见名称和规范化社区身份。
2. 在同一真实页面上下文点击或导航到最新回复、最新发布，记录实际目标URL、可见标签和来源关系。
3. 两个顺序分别验证、分别保存；只有一个顺序存在时只保留真实存在项。
4. 易车已标记缺失项记为 `source_missing_confirmed`，不加入分母。

### 阶段1：发现与样本冻结

1. 复用统一圈子发现接口，按来源分页取得帖子候选。
2. 规范化平台帖子身份与URL，同一平台内去重；重复项只保留一条并记录来源集合。
3. 对候选执行轻量现时有效性检查，排除明确不存在、非帖子页面、帖子ID冲突、列表声明原始归属与详情不符和控制页；平台明确聚合到当前来源的跨论坛帖子保留发现来源与原始归属双重身份，不在此阶段过滤。
4. 每个平台在正式运行前冻结500个不同有效URL，以UTF-8/LF写入清单，记录生成时间、发现来源分布、规范化版本、代码提交、访问模式和SHA-256。
5. 当前存在来源合计不足500个有效URL时，记录实际上限和来源分布，本平台验收门保持未关闭，不用重复URL或另一平台URL补足。

### 阶段2：项目生成功能样本

从冻结清单和发现过程按实际可观察事实选择功能子集，至少尝试覆盖：

- 普通文字帖、图片帖、视频帖和混合媒体帖；
- 零条、少于十条、不少于十条一级评论；
- 可见、明确隐藏或删除、状态不明；
- 匿名可访问、确需认证、认证失效和可识别平台控制；
- 长正文、特殊字符、跨页发现、重复候选和分页结束。

每条样本记录证据来源、确认时间和可失效条件。某场景在当前平台或样本池中没有观察到时记录 `not_observed`，不编造样本或期望值。

### 阶段3：适配器与公共行为验证

1. 新平台只新增统一采集器适配、字段映射、响应分类和平台安全上限，复用现有批次、平台FIFO、Session、存储、API、前端和导出。
2. 公共行为测试覆盖来源验证、分页停止、每来源有效目标数、详情身份、正文或媒体、最多十条一级评论、状态标准化、去重、错误分类、认证等待和检查点恢复。
3. 平台不存在的字段允许为空；可见状态证据不足时保存 `unknown`；平台原始状态与诊断证据继续保留。
4. 汽车之家和易车均通过官方页面建立独立加密 Session；人工认证操作只导出并保存服务器浏览器 Session，不访问圈子、首帖、点赞或用户消息接口。正式采集在每个真实任务中再检查平台账号 Cookie、身份接口及受保护字段响应，两平台采集都使用直连HTTP；访问模式变化后重新冻结运行条件并从头执行正式500条，不拼接历史匿名或访问会话结果。
5. 本地发布与正式验收分开判定：完成统一适配器、已确认真实平台样本、公共业务链和本地自动化闭环后可把平台发布为 `available`，但默认停用；本计划的正式500条、真实配置/任务/导出和环境证据全部通过后，才可声明正式生产接入验收完成。尚未实现页面证据的平台在手动与计划触发均按平台能力规范化为关闭且保留请求语义。

### 阶段4：每平台500条正式验收

每个平台单独运行，要求：

- 输入恰为事前冻结的500个不同、当前有效帖子URL；
- 500个输入均产生唯一终态，完成量为 `500 / 500`；
- 帖子身份与输入一致，真实正文或平台实际返回媒体满足必需内容合同；
- 主评论按平台当前响应最多保存10条；评论为空、数量差异或分页未结束不淘汰身份和正文或媒体有效的帖子；
- 登录页、验证码、挑战、限流、异常空响应和真实错帖不计为有效结果；发现来源与原始论坛不同但两层身份各自一致的跨论坛聚合帖计入有效结果；
- 自动恢复只在同次运行的有界预算内成功后计入完成，过程写入请求事件；
- 不进行人工补值、运行后删样本、跨平台补量或运行窗口后的结果拼接；
- 记录总耗时、有效URL/秒、请求放大率、P50/P95、峰值资源、访问模式、平台控制分布和恢复结果，但不设置2000条/小时或连续三轮门槛。

任一输入未形成满足合同的有效结果时，该平台本轮未关闭验收门。修复后使用新的完整冻结清单或在现时复核仍全部有效的原清单从头重跑，不把分段结果拼接为通过。

## 5. 口碑映射并行分析边界

- 项目可在帖子适配阶段并行生成汽车之家、易车各27款车型的映射候选：内部车型ID、平台稳定车型ID、规范页面URL、平台展示名和身份依据。
- 候选只进入现有单平台批量映射草稿；保存后仍为未验证，必须逐项完成身份、指标或明确暂无、指标区域证据三门禁，并由用户显式发布。
- 口碑评价篇数与差评率的页面或接口来源本阶段保持未决。即使车型身份映射已经验证，也只表示映射准备完成，不表示该平台五指标口碑适配完成。

## 6. 完成判定

单个平台只有同时具备以下证据才记为正式生产接入验收完成；本地 `available` 只表示代码、真实平台样本与本地业务闭环已发布：

1. 已存在来源清单及最新回复/最新发布关系证据；
2. 500条冻结清单、manifest和SHA-256；
3. 分层功能样本及覆盖缺口；
4. 公共行为测试和平台样本测试通过；
5. 正式 `500 / 500` 逐URL结果、汇总、环境、请求事件和校验清单；
6. 页面配置、手动提取、计划提取、批次详情和XLSX真实闭环；
7. 凭证、Session和完整业务URL均未进入Git、日志、前端列表或导出。

汽车之家与易车分别判定，不因其中一个平台通过而推定另一个平台的正式生产接入验收也已完成。
