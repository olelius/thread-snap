# 在线多模态舆情反馈 PoC 计划

## 1. 状态与目的

- 状态：方案已确认，尚未执行。
- 目的：用真实帖子验证在线模型服务能否直接读取 ThreadSnap 保存的图文和视频 URL，在一次请求中分别处理视频画面与音频，并稳定返回可追溯的结构化舆情反馈。
- 模型基线：阿里云百炼 OpenAI 兼容 Chat Completions API，固定快照 `qwen3.5-omni-plus-2026-03-15`，HTTP 非流式。
- 官方能力与调用参考：[全模态模型](https://help.aliyun.com/zh/model-studio/omni/)、[OpenAI Chat Completions 兼容接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。执行前必须重新核对固定快照仍可用及当日官方视频 URL、格式、大小和时长限制。

该 PoC 只形成事实报告，不做模型准确率验收。它不证明情感或分类在客观意义上正确，也不设置召回率、精确率、误判率、漏判条数、人工一致率或类别正确率门槛。

## 2. 已知基线与前置条件

当前本地业务库只读盘点得到：

| 项目 | 当前值 |
|---|---:|
| 帖子快照 | 2880 |
| 不同平台帖子 | 842 |
| 含图片快照 | 1939 |
| 含视频快照 | 0 |
| 图片数中位数 / P90 / P95 / P99 / 最大值 | 1 / 6 / 7 / 9 / 12 |
| 标题加正文字符数中位数 / P90 / P95 / P99 / 最大值 | 88 / 570 / 757 / 1242 / 1955 |

执行前必须具备：

1. 至少 30 条真实、当前可访问的视频帖子，均包含平台代码、帖子 ID、标题、正文、图片 URL 和完整视频 URL；
2. 覆盖短视频与相对长视频、近期与较早签名 URL、有声与无声、关键证据主要在画面、主要在音频、画面与音频含义不一致，以及明确失效 URL 对照样本；
3. 从现有数据库只读抽取一组纯文字和图文帖子，用于核对无媒体、单图和多图路径；
4. 在 Git 外配置 `API_KEY`、`BASE_URL`、模型快照、超时和并发。样本、签名 URL、原始响应和运行日志不得提交 Git。

样本不是人工金标准集。可以记录便于定位的客观媒体特征，但不要求单一复核者预先给出正确情感或类别。

## 3. 输入、请求与版本冻结

每个帖子独立发起一次请求，输入只包括：

- 当前快照的完整标题；
- 当前快照的完整正文；
- 当前快照的全部图片 URL，并为每项附加输入索引和去除时效签名噪声后的 URL 哈希；
- 当前快照的全部视频 URL，并为每项附加输入索引和去除时效签名噪声后的 URL 哈希。

主评论、楼中楼、作者历史、其他帖子、网页搜索结果和人工旧判定不进入模型输入。ThreadSnap 不下载、中转、转码、截断、抽帧或语音转写媒体；测试程序把媒体 URL 直接交给提供方，并服从模型官方限制。

每轮冻结并写入清单：

- 提供方、Base URL 区域和模型快照；
- system/user 提示词完整版本和 SHA-256；
- JSON Schema 版本和 SHA-256；
- 舆情判定对象版本及其品牌名、别名、产品和服务实体；
- 样本清单 SHA-256；
- 客户端提交、Python 和依赖版本；
- 超时、并发和重试配置；
- 运行开始、结束时间和网络出口说明。

## 4. 期望结构

模型原始响应完整保存；解析后的最小结构为：

```json
{
  "sentiment": "negative",
  "primary_category": "product_complaint",
  "secondary_categories": ["service_complaint"],
  "modalities": {
    "text": {"status": "processed", "evidence": ["..."]},
    "image": {
      "status": "processed",
      "expected_count": 2,
      "processed_count": 2,
      "items": [
        {"input_index": 0, "url_hash": "...", "status": "processed", "evidence": ["..."]}
      ]
    },
    "video_visual": {
      "status": "processed",
      "expected_count": 1,
      "processed_count": 1,
      "items": [
        {"input_index": 0, "url_hash": "...", "status": "processed", "evidence": ["..."]}
      ]
    },
    "video_audio": {
      "status": "speech",
      "expected_count": 1,
      "processed_count": 1,
      "items": [
        {"input_index": 0, "url_hash": "...", "status": "speech", "evidence": ["..."]}
      ]
    }
  },
  "summary": "..."
}
```

`sentiment` 只允许 `negative`、`non_negative`。负面类别只允许 `product_complaint`、`product_criticism`、`service_complaint`、`brand_criticism`、`competitor_attack`、`other`；非负面结果不填写主要类别。模态状态必须区分不存在、已处理、不可访问、不可辨认和未处理；视频音频还区分有语音、静音和无语音。

结构校验只回答字段和模态声明是否完整，不检查判断内容是否正确。图片、视频画面和视频音频必须按输入索引或 URL 哈希逐项声明，并使预期数量、已处理数量和明细一致；视频样本只有在模型明确返回画面覆盖和音频覆盖时才记为两种模态均已处理。

## 5. 失败处理边界

| 失败 | 处理 |
|---|---|
| 网络错误、超时、HTTP 429、5xx | 最多三次指数退避，逐次记录状态和耗时 |
| 提供方获取媒体 URL 失败 | 原 URL 再试一次；仍失败则记录 URL 哈希、媒体类型、提供方错误和 `analysis_partial` |
| 空响应或 JSON/Schema 无效 | 携带校验错误再试一次，保留每次原始响应 |
| 401、403、模型不存在 | 停止本轮后续请求，标记配置级暂停 |
| 内容策略拒绝 | 不重复请求，记录提供方原始拒绝和待人工处理 |
| 超过官方媒体限制 | 不截断或下载，记录限制项并形成部分结果 |
| 重试预算耗尽 | 记录最终失败，不补写推测结果 |

本轮不因 URL 直传失败自动增加后端下载、对象存储或媒体代理。报告完成后根据真实失败分布、URL 类型和成本再决定是否需要新的 ADR。

## 6. 执行步骤

1. 只读导出图文样本，收集并去重至少 30 条真实视频样本；对签名 URL 只在 Git 外清单中保存原值。
2. 记录样本清单哈希，冻结模型、提示词、Schema、舆情判定对象和运行配置。
3. 先以一条纯文字、一条多图、一条有声视频做连通冒烟，确认原始响应、请求 ID、用量和模态覆盖字段可取得。
4. 按受控并发执行全部样本；每条帖子一个请求，所有重试均写入同一条结果的尝试列表。
5. 对每条视频核对提供方是否取得 URL、是否分别声明画面与音频覆盖、返回结构是否有效；不评价情感和分类的对错。
6. 汇总成功、部分和失败的数量与分母，按媒体类型、URL 新旧、错误码和重试结果拆分，不只报告 HTTP 200。
7. 形成事实报告后决定：保持 URL 直传、调整模型/官方限制，或另立媒体中转决策；未取得报告前不实现下载回退。

## 7. 本地产物与结果格式

所有原始输入和结果位于被 Git 忽略的目录：

```text
artifacts/poc/
├── inputs/sentiment-analysis/
│   ├── posts.jsonl
│   └── manifest.json
└── results/sentiment-qwen3-5-omni-plus/<round-id>/
    ├── run-manifest.json
    ├── results.jsonl
    ├── summary.json
    └── run.log
```

`results.jsonl` 每条至少记录样本 ID、平台帖子身份、输入哈希、媒体数量、媒体 URL 哈希、提供方请求 ID、HTTP/提供方状态、原始响应文件引用、结构校验、各模态覆盖、重试明细、耗时、用量、估算成本和最终分析状态。`summary.json` 必须给出总分母以及完成、部分、失败的数量，URL 获取、画面覆盖、音频覆盖、结构有效的各自分母和比例，延迟分布、用量、成本及错误分布。

API Key、Cookie、Session、账号信息和带签名查询的完整 URL 不进入日志或汇总；原始输入和响应至少保留到舆情反馈增量完成验收，再由项目负责人手动决定是否删除。

## 8. PoC 后决策

PoC 结束后只依据可复核事实回答：

1. 当前模型是否能从实际 URL 取得每类媒体；
2. 视频画面和音频覆盖分别达到怎样的实际分布；
3. 结构化返回、延迟、用量和成本是否足以支撑后续实现设计；
4. 失败主要来自签名过期、防盗链、官方限制、格式、网络还是模型服务；
5. 是否继续使用该固定模型和 URL 直传，或需要另立模型/媒体传输决策。

任何“情感正确”“类型正确”“最多漏判若干条”均不由本 PoC 宣称。
